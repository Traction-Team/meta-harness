# Linking a factory

`metafab link` installs `.factory/` in the files and directories that agent tools read.

Edit `.factory/`, then run `metafab link`. Do not edit generated copies.

The installed output is committed. A fresh clone therefore contains the same factory for every team member and agent.

## Installed output

| Source | Destination | Target |
| --- | --- | --- |
| Each factory skill directory | `.claude/skills/<name>` | `claude` |
| Each factory skill directory | `.agents/skills/<name>` | `codex`, `opencode`, and compatible tools |
| Each factory skill directory | `.cursor/skills/<name>` | `cursor`, pending confirmation |
| Factory instructions, rules, workflows, stages, and decisions | Generated block in root `AGENTS.md` | All targets |
| Generated factory import | Root `CLAUDE.md` | `claude` |
| Built-in `metafab` skill | Each target's skill directory | All targets unless disabled |

A factory skill is any directory below `.factory/` that contains `SKILL.md`.

Metafab creates one installed entry for each unique destination. For example, `codex` and `opencode` share `.agents/skills/`.

## Target selection

`.factory/metafab.yaml` stores the default targets:

```yaml
agents: [claude, codex]
```

Target selection follows these rules:

1. `agents: all` selects every target supported by version 1.
2. On the first interactive run, `link` asks for targets when `agents` is absent.
3. On a non-interactive first run, `link` uses `all` when `agents` is absent.
4. `--agents claude,cursor` overrides the configuration for one command.
5. `--save` stores the command-line selection in `metafab.yaml`.
6. The next `link` removes owned output for targets removed from the configuration.

## Skill installation

In the default mode, Metafab creates relative directory symlinks:

```text
.claude/skills/review-slice -> ../../.factory/workflows/review-slice
.agents/skills/edge-cases   -> ../../.factory/scorers/edge-cases
```

Directory links include `SKILL.md` and all supporting files in the skill directory.

Relative links work in clones and Git worktrees. They do not depend on an absolute local path.

Agent tools use a flat skill namespace. A nested skill such as `.factory/review/security/` installs as `security`.

All skill names must therefore be unique across the factory.

### Ownership

Metafab records each installed path in `.factory/metafab.lock`. It changes or removes only recorded paths.

If an unowned destination has the same name as a factory skill, `link` stops with exit code 5. It does not replace that destination.

When a skill is removed from `.factory/`, the next `link` removes its owned installed entries.

### Installation mode

```yaml
link:
  mode: symlink
```

Supported modes:

| Mode | Behaviour |
| --- | --- |
| `symlink` | Creates relative directory symlinks. This is the default |
| `copy` | Creates directory copies and records their hashes |

Use `copy` when the platform or agent tool does not support symlinks. If symlink creation fails, `link` falls back to copies and reports the fallback.

`metafab check` fails when an installed copy differs from its source. This includes manual edits and stale copies.

## Root `AGENTS.md`

`metafab link` manages one block in the root `AGENTS.md`:

```markdown
<!-- factory:start -->
<!-- Generated by metafab link from .factory/. Edit .factory/, then run metafab link. -->

(contents of .factory/AGENTS.md)

## Rules

(contents of each .factory/rules/*.md file, ordered by file name)

## Workflows

Load the workflow that matches the request. Each workflow states what happens next.

| Workflow | Use when | Flow |
| --- | --- | --- |
| `file-work` | A person reports a bug, idea, or feedback | Start -> Logged ideas |
| `review-slice` | A slice PR is ready for review | Built branches -> Ready to merge |

## Flow

Logged ideas --triage-ideas--> Approved plans --build-slice--> Built branches --review-slice--> Ready to merge --> Shipped

People make these decisions:

- **triage** (product lead): Pick the next item.
- **done** (code owner): Approve the PR. Stop and wait for approval.

## Factory source

This repository stores its factory in `.factory/`. Edit that directory and run `metafab link`.
Do not edit generated copies in `.claude/` or `.agents/`.
<!-- factory:end -->
```

Metafab applies these rules to the block:

1. It creates `AGENTS.md` when the file does not exist.
2. It appends the block when the markers do not exist.
3. It replaces only the text between existing markers.
4. It preserves all text outside the markers.
5. It lists every workflow with its `description`, `from`, and `to` values.
6. It omits scorers and skills because agent tools discover them through skill directories.
7. It includes the flow only when `factory.yaml` defines stages.
8. It inlines all rules because every session must read them.
9. It warns when the generated block exceeds 300 lines.

The marker format is part of the open factory format. Other tools can generate the same block.

## Root `CLAUDE.md`

Claude Code reads `CLAUDE.md`. The `claude` target makes it import the root `AGENTS.md`.

`link` handles the file as follows:

1. If `CLAUDE.md` does not exist, create it with `@AGENTS.md`.
2. If it already imports `AGENTS.md`, leave it unchanged.
3. Otherwise, add `@AGENTS.md` in a marked factory block at the start of the file.

## Built-in `metafab` skill

`link` installs a built-in `metafab` skill for each target. This entry is a copy supplied by the CLI, not a link to `.factory/`.

The skill tells an agent how to:

- Find and edit factory source files
- Create workflows, scorers, skills, and rules
- Run `metafab link` after an edit
- Run `metafab check` and resolve each reported problem
- Keep factory changes in a reviewable commit or PR
- Review upstream changes from `metafab update`
- Design a factory by identifying stages, workflows, decisions, and current failures

The design guidance recommends four to eight initial stages with one workflow between each pair.

Disable this skill with:

```yaml
link:
  skill: false
```

`metafab check` detects an outdated built-in skill. `metafab link` replaces it with the current CLI version.

## Repeatability

`metafab link` writes, updates, or removes only out-of-date owned output. It reports every changed path.

A second run with unchanged inputs makes no changes.

`metafab check` fails when `link` would change a file. Teams can run it in CI or a pre-commit hook:

```sh
npx @seasb/metafab check
```
