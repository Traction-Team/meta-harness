# metafab stays inside your repository, leaves Factory.ai Droid's folder alone, and every command has its own --help

Inside a Git repository `metafab` now looks for `.factory/` only up to the repository's top level, and outside Git only in the current directory, so `metafab import` in a fresh repository no longer picks up `~/.factory/`. A `.factory/` with Droid's `settings.json` or `droids/` and no `factory.yaml` is refused with exit 5 before anything is fetched or written. `metafab import --help` (and every other command, `pipeline` included) prints that command's usage, arguments and options, also as JSON. Two answers piped in one chunk now answer two prompts, and end of input at a prompt exits 2. Directory walks work on filesystems that report no entry types, a symlinked Git hook gets a warning that names its target, and `update` and `import` print the `+ git hook` lines their build made.
