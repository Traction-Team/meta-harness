# Installed skills stay current after checkout, merge and rebase

Set `git-hooks: true` in `.factory/metafab.yaml` (or run `metafab init --git-hooks`) and every `metafab build` installs `post-checkout`, `post-merge` and `post-rewrite` hooks that run `metafab build`. A new `git worktree add`, a pull, a branch switch or a rebase now leaves the skills installed and current with no manual step. The hooks run the project's `node_modules/.bin/metafab`, then `metafab` on `PATH`, then `npx --yes @seasb/metafab@<version>`, and a failing build never fails the Git command.

`metafab init` asks about hooks in a terminal (yes by default), takes `--git-hooks` / `--no-git-hooks`, and never changes a value already set. It suggests adding `npx --yes @seasb/metafab build` to `scripts.setup` in `orca.yaml` when that file exists without it. Metafab never edits a hook it did not write: a foreign hook, a symbolic link at a hook path, or `core.hooksPath` gets a warning with the line to add by hand. `git-hooks: false` removes only Metafab's hooks. `init` also refuses to write through a symbolic link at `.factory/AGENTS.md` or `.gitattributes`. The built-in `metafab` skill explains every way to keep installed skills current.
