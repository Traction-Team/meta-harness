# Plan 1.025: Git hooks on in this repository

Since Plan 1.017 this repository builds its factory with `metafab build`, but Git hooks stay off (`git-hooks: false`) because the hooks run the project's `node_modules/.bin/metafab` first, and that needs `@seasb/metafab` as a devDependency, which needs the package on npm. Once Plan 1.012 publishes 1.0.0, this plan adds the devDependency and turns the hooks on, so a pull, a branch switch, a rebase or a new worktree keeps `.claude/skills/` and `.agents/skills/` current with no manual step.

Seen on 12 Nov: after pulling 1.017, the main checkout had no `.claude/skills/` or `.agents/skills/`, and agents lost every factory workflow without warning until `metafab build` ran. Until this plan merges, a pull that changes `.factory/` needs `npm run factory`.

## Decisions

| Topic | Choice | Reason |
| --- | --- | --- |
| Version range | `"@seasb/metafab": "^1.0.0"` in `devDependencies` | The hooks prefer the project's copy; a caret range follows patch and minor fixes |
| `orca.yaml` | Unchanged: `npm install`, `npm run build`, `node dist/cli.js build` | This repository tests its own checkout, so its worktrees build with the CLI they contain |
| `npm run factory` | Unchanged: it still runs `node dist/cli.js build` | Same reason; the hooks are for checkouts and pulls, not for CI |
