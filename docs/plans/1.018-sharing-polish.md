# Plan 1.018: Sharing edge cases and shared helpers

The cold reviews of PRs #12 to #16 left a list of small follow-ups. None of them loses data today, but together they make `update`, `import` and `check` behave differently across operating systems, and leave several helpers copied two or three times, so one copy can be fixed while another is missed. This plan closes them before the v1 release. After it merges, `update` keeps CRLF files as CRLF and restores `.factory/` if a write fails partway, `import --force` gives the same result on every filesystem, `diff` with no edits says so, `check` finds markers in a Latin-1 file that starts with `ÿþ`, and init, import, update, fetch and publish share one copy of each helper.

## Specs

- [Sharing: Merge rules](../specs/sharing.md#merge-rules): CRLF output, link conflicts, a failed update
- [Sharing: Importing a fab](../specs/sharing.md#importing-a-fab): `--force` with a case-only clash
- [Sharing: Comparing local edits](../specs/sharing.md#comparing-local-edits): `metafab diff` with no edits
- [Sharing: Supported sources](../specs/sharing.md#supported-sources): a Git fetch takes committed bytes exactly

Spec edits this plan makes. In `cli.md`, [Adopt existing skills](../specs/cli.md#adopt-existing-skills): a link that leaves `.factory/` after the move (directly or through a symlinked directory) is refused, and a link into another skill adopted in the same run is accepted. In `sharing.md`: the CRLF output rule, the link-conflict rule and the restore-on-failure rule (Merge rules); in Importing a fab, the `--force` realignment, and the sentence "`--force` permits those replacements" becomes "`--force` permits those replacements, including a case-only clash with a single local entry, which it renames to the fab's spelling. It never resolves two local entries that differ only in case from one incoming path"; and the no-edits line (Comparing local edits). 

## Decisions

Agreed with the person on 2026-11-08.

| Topic | Choice | Reason |
| --- | --- | --- |
| CRLF output of `update` | When every line of the local copy ends in CRLF, a clean merge, a take-theirs write and a conflict-marker file are written with CRLF. Otherwise the result is written with LF, as today. `.upstream` side files hold upstream's bytes unchanged (today they are normalised to LF) | The comparison already ignores CRLF; the write should not change a file's line endings when nothing else changed them |
| Link conflicts | A conflict where either changed side is a link is never merged as text: yours is kept and `<file>.upstream` is written as a text file holding upstream's link target (or upstream's file bytes, when upstream is a file). The conflict line is `Conflict in <path>: upstream is a link to <target>; its target is in <path>.upstream.`, or, when yours is the link and upstream a file, `Conflict in <path>: your entry is a link to <target>; upstream's file is in <path>.upstream.` | Symbolic links are unreliable on Windows; the text form works everywhere, it just needs saying |
| A failed `update` write | Snapshot `.factory/` before the first write. On any failure while writing or recording the upstream, restore it, leave the upstream record unchanged, and report the original error | A half-applied update with the old version recorded is the worst state: the next update would treat partial upstream content as local edits |
| `import --force` with a case-only clash | Rename the local entry to the fab's spelling first, using `alignFactorySpelling`, then copy. Local-only files beneath it move with it; nothing is deleted | Today macOS and a case-sensitive filesystem give different trees |
| `metafab diff` with no edits | Print `No local edits since <source> <label>.` (`<label>` from `recordedLabel`, or nothing for an unversioned source) | Today it prints a blank line |
| `update --to <range> --dry-run --json` | Include `requested` | A JSON caller must see the range it would record |
| Permission differences | Only the executable bit counts, everywhere `import` and `update` compare modes: the review summary, `update`'s change detection, and the merge | Matches `build`, which installs 0755 or 0644 |
| A mode-only difference with no base | Not listed under "Local edits preserved"; the note stays, and JSON gets `modeOnly: string[]` | The content matches upstream, so it is not a local edit |
| UTF-16 BOM in a non-UTF-16 file | When a UTF-16 BOM is present, scan both the UTF-16 decode and the lenient UTF-8 decode, and report the markers either finds, once per line | A file starting with `ÿþ` in Latin-1 has the bytes of a BOM; scanning both is simpler and safer than a heuristic |
| Adoption links | A link that leaves `.factory/` through a symlinked directory is refused with the `... after the move` wording (exit 5, as today). A link into a sibling skill adopted in the same run passes, because it works after the move | Completes Plan 1.014's rule that `treeProblems` is the one gate for links; `compileSkill` must not refuse a link the gate accepted |
| `upstreamFor` in update | Keep it, with a comment pointing at `upstreamEntry` in `src/core/sources/git.ts` and `npm.ts` | It keeps the recorded `source` spelling, which `upstreamEntry` rebuilds from the spec; merging them would change recorded sources |
| Case-clash wording | One `differentSpelling(file, incoming, command)` and one `ambiguousSpellingProblem(files, incoming, command)` in `conflicts.ts`; `command` picks the subject (`The incoming fab writes` / `The update writes`) and the fix (`run metafab import --force` / `Move the local entry away, then run metafab update again`) | Today's two messages stay exactly as they are; only the code is shared |
| `cliVersion` | Every copy goes; all callers use `src/util/version.ts`. `src/cli.ts` drops `packageVersion()` | Four copies of one function |

## Design

### Shared init and import helpers (`src/core/setup.ts`, new)

Move from `src/core/init/run.ts` and delete the copies in `src/core/import/run.ts`:

```ts
export type SetupCommand = "init" | "import";
export function selectedTargets(selection: "all" | Target[]): Target[];
export function unreadableFactory(file: string, message: string, fix: string): MetafabError;
export async function assertFactoryDirectoryUsable(factoryDir: string, command: SetupCommand): Promise<void>;
export async function readConfig(factoryDir: string, command: SetupCommand): Promise<Config>;
export async function preflightBuild(root: string, config: Config, selection: "all" | Target[], configExists: boolean, moves: readonly AdoptionMove[]): Promise<void>;
```

`command` fills the `then run metafab <command> again` fix lines, which are the only text that differed. `readConfig` uses `unreadableConfigCode` from `src/core/config/load.ts` and `unreadableConfigFix(code, command)`, which moves into `setup.ts` too (`Check its permissions or restore the file` for `EACCES`/`EPERM`, else `Restore the file, then run metafab <command> again`), so `import` stops matching the text `Cannot read .factory/metafab.yaml` and gives the right fix for `EIO` or `EISDIR`. `preflightBuild` uses `cliVersion()` from `src/util/version.ts`. `isAdoptionSource` moves with it.

### Shared update and import helpers

- `src/core/import/conflicts.ts` exports `ancestors`, the generic `indexOf<T>` (one list of entries per folded name, as `clashes.ts` has it), `differentSpelling(file, incoming, command: "import" | "update")` and `ambiguousSpellingProblem(files, incoming, command)` (moved from `clashes.ts`). `src/core/update/clashes.ts` imports them and deletes its copies. Every existing update message stays word for word, pinned by tests.
- Import's index changes from "first local entry per folded name" to the full list. When two local entries fold to one incoming path (possible on a case-sensitive filesystem), `findImportConflicts` reports one problem naming all of them: `The incoming fab writes <incoming>, but these local entries differ only in case: <a>, <b>`, fix `Move all but one of the local entries away, then run metafab import again`. `findImportConflicts` returns `{ conflicts: Problem[]; ambiguities: Problem[] }`. `runImport` throws `importConflicts([...ambiguities, ...conflicts])` (exit 5) whenever `ambiguities` is non-empty, even with `--force`, at the point where it checks conflicts today, before consent and before any write. So `alignFactorySpelling` never meets an ambiguous path during import.
- `src/util/text.ts`: delete the unused `isBinary` and its test in `test/cli/text.test.ts`. `textContent` in `src/core/build/skill.ts` stays the one classifier.
- `src/core/update/run.ts` and `src/core/import/run.ts` use `cliVersion()` from `src/util/version.ts`. `src/cli.ts` replaces `packageVersion()` with it (the `../../package.json` specifier is right from `dist/util/`, and `--version` is tested from `dist` in `test/cli`).

### Shared Git process helpers (`src/core/sources/git-process.ts`, new)

Move from `src/core/sources/git.ts` and delete the copies in `src/core/publish/git-target.ts`:

```ts
/** `core.hooksPath=<empty temporary directory>`, created once per process. */
export function disabledHooksConfig(): string;
/** `withEnv(env, interactive ? {} : { GIT_TERMINAL_PROMPT: "0" })`. */
export function gitEnvironment(env: NodeJS.ProcessEnv | undefined, interactive: boolean | undefined): NodeJS.ProcessEnv;
/** The trimmed, non-empty lines of stderr, then stdout, then the message. */
export function gitMessage(failure: { stdout?: string; stderr?: string; message?: string }): string;
/** The conversion attributes both publish and fetch turn off. */
export const VERBATIM_TEXT_ATTRIBUTES = "-text -eol -filter -ident -working-tree-encoding";
```

- `git.ts` builds `VERBATIM_ATTRIBUTES` as `` `* ${VERBATIM_TEXT_ATTRIBUTES} -export-subst -export-ignore\n` ``. The resulting string must stay byte-identical, because it feeds `FAB_FETCH_FORMAT`, the cache key: a test pins the full string and the `FAB_FETCH_FORMAT` value.
- `git-target.ts` uses `` `* ${VERBATIM_TEXT_ATTRIBUTES}\n` `` and keeps a one-line comment saying why publish does not need the export rules or `tar.umask` (it never runs `git archive`).
- Each module keeps its own `runGit`/`tryGit`, because their error types and arguments differ (fetch gives `fetch-failed`, publish gives `publish-git-failed`). Both call the shared helpers.

### Update

- **Dry run with `--to`** (`runVersioned`, the `sameVersion` branch): the dry-run return also sets `requested: range`.
- **Mode-only, no base**: in the `base-unavailable-mode` case, do not push to `preserved`; push to a new `UpdateReport.modeOnly: string[]`. The note stays. Add `modeOnly` to `MergePlan`, to the fields `baseReport` picks and to its literal (empty array), so every report carries it. `src/commands/update.ts` adds `modeOnly` to the JSON result.
- **Executable bit only**: export `modeMatters(left: { mode: number; link?: string }, right: { mode: number; link?: string }): boolean` from `src/core/summary.ts` (false when either is a link, else compares whether `mode & 0o111` is non-zero). Every mode comparison uses it: `modeDiffers` in `summary.ts`, `entriesDiffer` in `update/run.ts`, `sameEntry` in `update/trees.ts`, and `sameInput`, the direct mode comparison in `mergeWithoutBase` (~line 223) and the `take-theirs` mode in `merge.ts` (which becomes `modeMatters(yours, theirs) ? modeOf(theirs) : modeOf(yours)`). `modeOf` stays `mode & 0o777`, because it is the mode written by `chmod`, not a comparison. `mergedMode` returns yours unchanged when `!modeMatters(yours, theirs)`, so a 0644 file stays 0644 when upstream has 0664. `MergeInput` gains `link?: string`, filled by `mergeInputOf`. So a 0644 → 0664 change is no difference at all, with or without a base. Rewrite the existing test at `test/core/update/update.test.ts` (~line 1009) that expects such a change to be kept as a local edit. A test pins the link hash format with a literal, not `LINK_HASH_PREFIX`, in `test/core/summary/trees.ts`.
- **CRLF**: today the local tree stores `text: toLF(decoded)` and `entryFromContent` normalises again, so neither `merge.ts` nor `writeEntry` can see a CRLF file. Carry the line ending as data instead:
  - `FileEntry` (`src/core/import/file-tree.ts`) gains `crlf?: true`, set in `entryOf` when the decoded text has at least one line break and every `\n` is preceded by `\r` (helper `usesCRLF(text)` in `src/util/text.ts`). Hashes and comparisons stay on the LF text, so nothing else changes.
  - `run.ts` decides per path when it builds the planned write: a `write` carries `crlf: true` when `before[path]` (the local entry) has `crlf`, and `writeEntry` then converts the text with `toLF(text).replace(/\n/g, "\r\n")` after `entryContent`. This covers `merged`, `take-theirs` and conflict-marker results. Binary content is never converted.
  - An `add` (a file only upstream has) writes upstream's `raw ?? text`, so an upstream CRLF file lands as CRLF.
  - `FileEntry` also gains `raw?: Buffer`: `entryOf` keeps the file's original bytes for a text entry when they differ from the LF text (so only CRLF or mixed files pay for it). Side files are written from upstream's bytes: the `side-file` write carries `raw ?? Buffer.from(text)` of the upstream entry, and `applyWrites` writes that buffer with `writeEntry` directly, without `entryFromContent`.
  - Comparison stays CRLF-insensitive, so a second update reports nothing.
- **Link conflicts**: `SideFileReason` in `merge.ts` gains `"link"`. `MergeInput.link` (added above) is compared in `sameInput`, so a link and a file with the same bytes differ. The link test runs in three places, each before any text handling: in `mergeChanges` before the `sameContent` shortcut, in `mergeWithoutBase`, and in `mergePath`'s conflict branch. When yours and theirs differ and either is a link, the result is `side-file` with reason `link`, plus `yoursLink?: string` and `upstreamLink?: string` so `conflictNote` can print the target. The side-file content is `Buffer.from(upstreamLink)` when upstream is a link, else upstream's `raw ?? Buffer.from(text)`. `update/run.ts` prints the matching line from Decisions.
- **Restore on failure** (`src/core/update/restore.ts`, new):

  ```ts
  export interface FactoryCapture { restore(): Promise<void>; discard(): Promise<void> }
  /** Not `snapshotFactory`: `import/file-tree.ts` already exports that name with another meaning. */
  export async function captureFactory(factoryDir: string): Promise<FactoryCapture>;
  ```

  `captureFactory` walks `.factory/` itself and records every entry: files (raw bytes and mode), links (target), and directories (including empty ones), with their exact spelling, and copies file bytes into a `mkdtemp` directory. `restore` makes `.factory/` match the record exactly: it deletes entries not in it, recreates every recorded path that is absent (files, links and directories, empty ones included), rewrites files whose bytes or full mode differ and links whose target differs, and renames a file or directory back when only its case differs. `runVersioned` and `runUnversioned` call `captureFactory` just before the first write and wrap the writes, `alignFactorySpelling` and `setUpstream` in `try`. On failure they `restore()` and throw `MetafabError("Update stopped: <original message>. .factory/ was restored.", { exitCode: ExitCode.Failed, code: "update-write-failed", cause })`. If `restore` itself fails, the message instead says `.factory/ may be partly updated` and the fix is `Restore .factory/ from Git (git status shows what changed), then run metafab update again`. `discard()` runs in `finally`. The closing build is outside the wrapped block: a build failure never rolls back. A dry run captures nothing.

### Diff

`describeDiff` (`src/core/update/diff.ts`) returns `No local edits since <source> <label>.` when `files` is empty, using `report.upstream.source` and `recordedLabel` for a versioned upstream, and `No local edits since <source>.` for an unversioned one. With a path limit: `No local edits in <prefix> since …`.

### Import

- **`--force` with a case-only clash**: immediately before `copyFactoryTree` (after consent, so a declined import changes nothing), call `alignFactorySpelling(factoryDir, { files, directories })` with the fab's file paths minus `FAB_ROOT_EXCLUDES`, and `directories` from `snapshotDirectories(fetched.factoryDir)` as `runUnversioned` does, so an empty fab directory is realigned too. A path component whose local entry is not a directory is skipped (today's file → directory replacement, which `copyFactoryTree` handles, keeps working). `alignFactorySpelling` must therefore tolerate `ENOTDIR` on such a component; change it in `src/core/update/spelling.ts` so it skips that component, and test that update is unaffected. Local-only files beneath a renamed directory move with it.
- **Conflict grouping** (`conflicts.ts`): a case-only clash on a local directory gives one problem, whose `file` is the local directory and whose message names the incoming directory spelling, not one per incoming file beneath it.
- **Review summary**: no change beyond `modeMatters`.

### Check (`src/core/check/markers.ts`)

`detectEncoding` keeps its order. When it returns `utf-16le` or `utf-16be`, `readTextFile` also decodes the bytes leniently as UTF-8, and the marker scan runs over both texts. The rule stays one problem per file (pinned by the existing "reports only the first marker line in each file" test): it names the lowest line on which either decode finds a marker. UTF-32 and BOM-less UTF-16 stay binary.

### Adoption (`src/core/adopt.ts`)

- `treeProblems` resolves the link target's real path (with `realpath` on the part that exists, as the loop check does at line ~107) before deciding whether it stays inside `.factory/`. A link that leaves through a symlinked directory is refused there with `Symlink <path> points outside .factory/ after the move`.
- A target inside another skill adopted in the same run already counts as inside: `treeProblems` judges the post-move path (`realPathOf(destinationTarget)`), so no change is needed there.
- `checkSkillTree` must not refuse what `treeProblems` accepted. `compileSkill` runs on the pre-move tree and realpaths each root, so it is given the current source directories (`from`) of every skill adopted in the run as extra `linkRoots`: a link to `../reference/notes.md` resolves into the sibling's current directory, which exists. Build itself still never passes `linkRoots`.
- The test in `test/core/adopt/adopt.test.ts` that pins build's wording changes to the new wording.

### Import: no writes through a dangling `.gitattributes`

Plan 1.016 adds `assertGitattributesWritable(root, command)` to `src/core/init/gitattributes.ts` and calls it from `init`. `runImport` calls it too, at its conflict check, before consent and before any write.

### Tests only

- `test/core/import/import.test.ts`: the empty-directory conflict test compares the repository snapshot before and after.
- `test/core/check/markers.test.ts`: a UTF-16LE and a UTF-16BE case with the marker on line 1.
- HTTPS fetch tests in `test/core/sources/` remove their fetched temporary directories in `afterEach`.
