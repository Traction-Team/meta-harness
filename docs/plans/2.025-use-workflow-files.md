# Plan 2.025: fab-basic 0.3 keeps its workflows as plain files and this repository updates to it

fab-basic 0.3.0 sits on an unpushed branch, `feat/dragonfly-handover` (`00cd788`), in another thread's orb. It held back renaming its workflows from `SKILL.md` because Metafab 2.0.0 could not read the new layout. Once Plan 2.024 has published 2.1.0, fab-basic renames its nine workflows to `.factory/workflows/<name>.md`, moves to `format: 3`, and drops its hand-written workflow table, because Metafab now writes one. This repository then updates to it, as Plan 2.018 did for 0.2.1.

## Specs

- [Factory format: Workflows](../specs/factory-format.md#workflows)
- [Building: Root `AGENTS.md`](../specs/building.md#root-agentsmd)
- [Sharing: Updating](../specs/sharing.md)

This plan changes no spec.

## Decisions

| Topic | Choice | Reason |
| --- | --- | --- |
| Form of each workflow | `workflows/<name>.md` for a workflow with no supporting files; `workflows/<name>/workflow.md` for one with them. Today none has supporting files, so all nine become `<name>.md` | The person's two forms; the simplest one fits |
| Which workflows stay skills | None. `skills/stacked-prs/SKILL.md` stays a skill | The person does not want workflows in the harness skill list |
| fab-basic's "Factory workflows" table in `.factory/AGENTS.md` | Removed. Its "when to run it" text moves into each workflow's `description`, which the generated table shows | One table, generated from the source |
| Text that says a workflow "is installed as a skill" or tells an agent to "load the workflow" as a skill | Reworded to "read `.factory/workflows/<name>.md` and follow it" | The workflows are no longer skills. For example plan-feature's review brief says "Load the review-plan workflow" |
| fab-basic version | 0.3.x: 0.3.0 if it is not yet tagged, otherwise the next patch | The workflow rename and format 3 are a breaking change for importers on Metafab 2.0 |
| Where 0.3.0's unpushed branch goes | Its owner thread pushes `feat/dragonfly-handover` and opens its pull request first; this rename is a commit on top of it or a follow-up pull request | It is not in this orb, and its work is not this plan's |

## Design

**Part A, in `github:Traction-Team/fab-basic`, before this repository's pull request.**

- `git mv .factory/workflows/<name>/SKILL.md .factory/workflows/<name>.md` for each of the nine. Remove `name:` from their frontmatter. Fix each `factory:import` path: `../../partials/x.md` becomes `../partials/x.md`, because the file is one level higher.
- Each `description` says when to use the workflow, folding in the matching row of the old table.
- `factory.yaml`: `format: 3`. `.factory/AGENTS.md`: delete "Factory workflows" and its table; keep "When a request matches a row, load that workflow" as one sentence pointing to the generated Workflows table.
- Grep the factory for `SKILL.md`, "installed as a skill" and "load the ... workflow"; reword each place that means a workflow. `.factory/docs/process.md` says workflows are read from `.factory/workflows/`.
- README and CHANGELOG: 0.3 needs Metafab 2.1.0 (`npx --yes @seasb/metafab` installs it); importers on 2.0 must upgrade; after updating, the nine workflows leave `.claude/skills/` and `.agents/skills/` on the next build.
- CI green, merge, tag.

**Part B, this repository's pull request.**

0. `npm view @seasb/metafab version` prints `2.1.0` or later. Until it does, the plan stays `draft`.
1. `npm install --save-dev @seasb/metafab@^2.1.0`.
2. `node dist/cli.js update --to ^0.3.0`; the review summary lists nine new workflow files, nine removed skill workflows, the format change and the table removal. `node dist/cli.js build` removes the nine installed workflow skills. `node dist/cli.js diff` prints no local edits.
3. `docs/factory.md` notes: the devDependency is `^2.1.0`; a new orb or worktree installs only `stacked-prs` and `metafab` as skills, and agents read workflows from `.factory/workflows/`. The repository root `AGENTS.md`'s own text that names workflows as skills ("Coding sub-agents run as ...", "Factory workflows") is checked and reworded where it is now wrong.

**Failure.** If 2.1.0 is not on npm, step 1 fails and nothing changes: stop. If `update` shows conflicts in `.factory/`, resolve toward upstream and carry the local edit to fab-basic. If fab-basic's CI fails, do not tag.

**Second run.** `update` again reports nothing to do; `build` reports `Up to date.`
