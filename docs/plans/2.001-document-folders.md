# Plan 2.001: A factory declares its document folders and check validates their documents

A factory's workflows keep plans, intake notes and changelog entries in folders, and each kind of document needs certain properties. Today this repository checks them with its own script, `.factory/scripts/check.mjs`, and every other factory must write one. After this plan, `factory.yaml` with `format: 2` can declare `documents`: each folder, a JSON Schema for its documents' frontmatter, properties that must be unique, and properties that reference other documents. `metafab check` validates every matching document. The declaration is factory content, so a fab ships it. It works whether the documents are in Git or, after Plans 2.004 and 2.005, in the metastore, and `metastore push` reuses the same checks. This is the first version 2 plan; it introduces `format: 2`.

## Decisions

Proposed in this plan, for approval:

| Topic | Choice | Reason |
| --- | --- | --- |
| Where rules live | `documents` in `factory.yaml`, schemas as files in `.factory/` | Rules are factory content a fab ships; where documents live is the repository's choice in `metafab.yaml` |
| Rule language | JSON Schema draft 2020-12 through `ajv` (`Ajv2020`), `allErrors: true`, `strict: true`, `validateFormats: false`; only `$ref` within the same file | A standard any backend can run later (Metastore Cloud); strict mode catches typos in a fab's schema; `format` stays an annotation so no extra package is needed |
| Schema file formats | `.json`, `.yaml`, `.yml` | This repository writes YAML; JSON for authors who prefer it |
| Cross-document rules | Only `unique` (error) and `references` (warning) | What Dragonfly needed: unique plan codes, and `needs` that may name a plan not yet written |
| Format version | `format: 2` gates `documents` (and scorers, Plan 2.008) | A 1.x CLI refuses an unknown format with a clear error, not "unknown field documents" |
| Documents with no frontmatter | Properties are `{}`; the schema decides whether that is an error | A changelog folder may not need properties; a plan folder's schema requires them |
| Problem level for schema violations | Error | A factory that declares a schema means it |
| Where the portable path rules live | `src/util/portable-path.ts`, moved out of Plan 1.023's `src/core/requires/paths.ts` | Document folders, store paths (Plan 2.002) and requirements share them |

## Design

### Portable path rules (`src/util/portable-path.ts`, new)

Move from `src/core/requires/paths.ts` (Plan 1.023), unchanged in behaviour:

```ts
/** The first portability rule a segment breaks, as a phrase, or undefined. */
export function portableSegmentProblem(segment: string): string | undefined;
/** Relative, `/`-separated, no empty, `.` or `..` segment, every segment portable. */
export function portablePathProblem(path: string): string | undefined;
/**
 * A folder the metastore may manage (document folders here; the mirror root and store folders in Plan 2.002):
 * `portablePathProblem`, at most 400 characters and 200 per segment, no segment starting with `.`,
 * and none of `!`, `#`, `[`, `]`, so it can be written to `.gitignore` and used as a Git pathspec as it is.
 * Takes the folder without its trailing `/`.
 */
export function folderPathProblem(folder: string): string | undefined;
```

`requirementPathProblem` in `src/core/requires/paths.ts` keeps its extra rules (forbidden targets, case clashes) and calls these. 1.023's tests must pass unchanged.

### Types (`src/core/factory/types.ts`)

```ts
export interface FactoryYaml {
  format: 1 | 2;
  // ...existing fields
  documents: DocumentFolder[];       // [] when absent
}

export interface DocumentFolder {
  folder: string;                     // repository-relative, ends with "/"
  description: string;
  match: string[];                    // ["**/*"] when absent
  schema?: string;                    // repository path, starts with ".factory/"
  unique: string[];
  references: string[];
  line: number;                       // line of the entry in factory.yaml
}
```

### Parsing (`src/core/factory/factory-yaml.ts`)

- `KNOWN_FACTORY_FIELDS` gains `"documents"`. A `format` of `2` is accepted (`isFormatOne` in `validate.ts` becomes `isKnownFormat`, true for 1 and 2; rule 7's message becomes `"format" must be 1 or 2`, fix `Set format: 2 to use documents and scorers, or format: 1`).
- New `parseDocumentFolder(itemNode, parsed, file, problems): DocumentFolder | undefined`, shaped like `parsePipelineEntry` and 1.023's `parseRequirement`. Messages, all errors on the entry's or key's line:
  - `documents` not a list: `"documents" must be a list`, fix `Write each folder as a - folder: entry`
  - entry not a mapping: `documents entry must be a mapping`, fix `Use - folder: docs/plans/\n  description: <text>`
  - unknown key: `Unknown key "<key>" in a documents entry`, fix from `didYouMean(key, ["folder", "description", "match", "schema", "unique", "references"])`
  - missing `folder` / `description`: `documents entry is missing "<key>"`
  - wrong type: `"<key>" in a documents entry must be <a non-empty, single-line string | a non-empty string or a non-empty list of non-empty strings>`. So `match: ""`, `unique: []` and `references: [""]` are errors; a key that is absent takes its default.
- `documents` with `format: 1`: one error on the `documents` key line, `"documents" needs format: 2`, fix `Set format: 2`. The entries are still parsed, so their own errors are reported too.

### Validation rule 14 (`src/core/documents/declarations.ts`, new; called from `load.ts`)

`export async function documentFolderProblems(factory: Factory, folders: DocumentFolder[], file: string): Promise<Problem[]>`, run by `loadFactory` after `parseFactoryYaml`, as 1.023's `requirementTemplateProblems` is. For each entry, in order, the first problem only:

1. `folder` does not end in `/`: `Document folder "<f>" must end with /`.
2. `folderPathProblem(folder without its trailing /)` returns a phrase: `Document folder "<f>" <phrase>`.
3. The folder is `.factory/`, `.claude/skills/`, `.agents/skills/`, or below one, or its first segment is `.git` in any case: `Document folder "<f>" is inside <x>`.
4. Equal to an earlier folder ignoring case, or below one, or above one: `Document folder "<b>" overlaps "<a>"`, fix `Remove one of the entries`.
5. A `match` glob that `picomatch.scan` rejects, that starts with `/`, or that has a `..` segment (`../x`, `a/../b`; a name such as `file..md` is fine): `Glob "<g>" in documents is not a relative glob`.
6. `unique` or `references` names that break `/^[a-z][a-z0-9_-]*$/`: `Property name "<n>" must start with a lowercase letter and use lowercase letters, digits, _ and -`.
7. `schema`: not starting with `.factory/`, a remainder that fails `portablePathProblem` (so `.factory/../x.yaml` is refused), or an extension other than `.json`, `.yaml`, `.yml`: `Schema "<s>" must be a .json, .yaml or .yml file in .factory/`. A path that exists but whose `realpath` is not inside the `realpath` of `.factory/` (a link out of the factory): `Schema "<s>" resolves outside .factory/`. Missing: `Schema "<s>" does not exist`. Unreadable: the existing `Cannot read file <s>`. Unparsable: `Schema "<s>" is not valid <JSON|YAML>: <first parser message>`, with the schema file and its line as `file` and `line`. Not a valid 2020-12 schema (`ajv.compile` throws): `Schema "<s>" is not a valid JSON Schema: <ajv message>`, on the `factory.yaml` entry line. A `$ref` that does not start with `#`: `Schema "<s>" refers to another file: <ref>`, fix `Copy the definition into $defs`.

Each problem's fix, unless given above, is `Correct the documents entry in .factory/factory.yaml`.

Compiled validators are cached per schema path for one process in `src/core/documents/schema.ts`: `loadSchema(root, schemaPath): Promise<{ validate: ValidateFunction } | { problem: Problem }>`.

### Reading a document's properties (`src/core/documents/parse.ts`, new)

```ts
export type DocumentFormat = "markdown" | "html" | "file";
export function formatForPath(path: string): DocumentFormat;   // .md / .html, case-insensitive; else "file"
export interface ParsedDocument {
  format: DocumentFormat;
  properties: Record<string, unknown>;     // {} when there is no frontmatter or comment
  body: string;                             // "" for file
  /** Line of each top-level property key in the file, 1-based. */
  propertyLines: Map<string, number>;
  /** First line of the frontmatter or comment, or 1. */
  propertiesLine: number;
  problems: Problem[];                      // YAML that is not a mapping, duplicate keys, aliases past the limit
}
export function parseDocumentText(file: string, text: string): ParsedDocument;
```

- Text is decoded by the caller. `parseDocumentText` removes a leading BOM and converts CRLF to LF (`toLF` from `src/util/text.ts`).
- Markdown: frontmatter only when the text starts with `---\n` and has a closing `---` line (reusing the scan in `src/util/frontmatter.ts`; a missing frontmatter is not a problem here, unlike for skills). The YAML goes through `parseYaml` with `lineOffset`, so duplicate keys and the alias limit give problems with real lines. A frontmatter that is not a mapping: `Frontmatter must be a mapping`. An unterminated `---`: `Unterminated frontmatter: add a closing --- line`.
- HTML: properties only when the text starts with `<!--metastore\n`; the YAML up to the first line that is exactly `-->` is parsed the same way. With no such line: `Unterminated properties comment: add a line with only -->`, error, on line 1.
- YAML is parsed with the core schema, so timestamps stay strings (`2026-11-14`). The `yaml` package's default `parseDocument` options already do this; a test pins it.
- Plan 2.002 adds the writer (`serializeDocument`) beside this reader.

### Checking documents (`src/core/documents/check.ts`, new)

```ts
export interface DocumentSet {
  /**
   * Documents that exist but have no file on disk, by repository path, with their stored properties
   * (from the index, Plan 2.006; or the metastore's list, Plan 2.009). They count for `unique` and
   * `references`, never for schema checks.
   */
  indexed?: ReadonlyMap<string, Record<string, unknown>>;
}
export async function documentProblems(factory: Factory, set?: DocumentSet): Promise<Problem[]>;
export async function documentProblemsFor(
  factory: Factory,
  folder: DocumentFolder,
  documents: ReadonlyMap<string, ParsedDocument>,   // repository path → parsed; every file under the folder
  set?: DocumentSet,
): Promise<Problem[]>;
export function uniqueKeys(value: unknown): string[];   // the JSON text of each value that counts
```

`documentProblems` lists each folder with `listFiles` (skipping directories whose name starts with `.`, and following no links out of the repository), reads each file as UTF-8 (a decode error: `<path> is not UTF-8`, error), parses it with `parseDocumentText`, and calls `documentProblemsFor`. `documentProblemsFor` itself keeps only the documents whose folder-relative path matches a `match` glob (`picomatch(globs, { dot: false })`), and only the `indexed` entries below the folder that match and have no entry in `documents`, so every caller passes whole folders and gets the same filtering. Plans 2.005 and 2.009 call `documentProblemsFor` with the documents they are about to save.

For each markdown and HTML document, in path order:

- Its parse problems, as errors on the document.
- Schema: each `ajv` error becomes one error. `file` is the document, `line` is `propertyLines.get(<first instancePath segment>)` or `propertiesLine`. The message is `Property "<instancePath without leading />" <ajv message>`; `required` errors become `Missing property "<missingProperty>"`, and `enum` errors append `: <allowedValues joined with ", ">`. Fix: `Correct the frontmatter; the rules are in <schema>`.
- `unique`: `uniqueKeys(value)` returns the distinct `JSON.stringify` texts of the value when it is a string, number or boolean, or of each such item when it is a list (so a value repeated in one list counts once); otherwise `[]` (so `null`, empty lists, mappings and nested lists do not count). Per property, a map from key to the first repository path, over the documents on disk and the `indexed` entries together, in path order. For each collision, the problem goes on the later of the two paths that has a file on disk, naming the other: `Property "<p>" value <key> is also used by <other path>`, error, fix `Choose another value`. Two `indexed` entries that collide give no problem here; `check` cannot point at a file, and the metastore holds them as saved.
- `references`: each string value, or string item of a list value, that has no URL scheme (`/^[a-z][a-z0-9+.-]*:/i`). Strip a trailing `@v<digits>`. When `portablePathProblem(value)` returns a phrase (an absolute path, `..`, `\`), warning `Property "<p>" value <value> is not a repository path: <phrase>`, and nothing is read for it. Otherwise, when neither `pathExists(root/value)` nor `set.indexed?.has(value)`: warning `Property "<p>" names <value>, which does not exist`, fix `Create it, or correct the path`. Root files such as `README.md` are valid references. `indexed` entries are not checked for their own references, only counted as targets.

`file` documents (any other extension) are skipped.

### Check (`src/core/check/index.ts`)

`runCheck` adds `documentProblems(factory)` after the requirement warnings and before the build errors, only when `factory.factoryYaml` parsed and `documents` is non-empty. Its doc comment's order sentence gains "document problems" in that place. Document problems never count as planner errors, so they never suppress the drift check.

### Publish

`createPackageJson` in `src/core/publish/package-json.ts` already writes `metafab.format` from `factory.factoryYaml?.format`; a test pins that a format 2 factory publishes `format: 2`. `validateFab` accepts format 2 through `loadFactory`.

### Edge cases

- **No documents declared.** Nothing changes; `check` reads no extra file.
- **A declared folder that does not exist.** No documents, no problem.
- **CRLF, BOM.** Normalised before parsing; line numbers count LF lines.
- **Non-UTF-8 document.** One error naming the file; the other checks skip it.
- **Large folders.** Files are read one at a time; validators are compiled once.
- **Windows.** Paths are POSIX in `factory.yaml` and in problems; `listFiles` already returns POSIX relative paths.
- **A schema with `format: date`.** Accepted as an annotation and not enforced; a test pins it, so a later change to enforce formats is deliberate.
