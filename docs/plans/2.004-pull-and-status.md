# Plan 2.004: Metastore pull fills a gitignored mirror, with status, show and log

This plan makes the metastore readable from a working tree. `metafab metastore pull` copies every document into the store folders under the mirror root and records what it wrote in `<root>/.metastore/state.json` and `<root>/.metastore/index.json`. It never overwrites or removes a local change: a newer version beside a local edit becomes a conflict copy in `<root>/.metastore/remote/`. `status` reports what differs, `show` prints any version, and `log` lists a document's history. `metafab build` adds the store folders and `<root>/.metastore/` to its `.gitignore` block, and every mirror command refuses a store folder that Git still tracks. Sync windows and pins come in Plan 2.006; until then a pull copies everything. After it merges, a team can fill its mirror from a metastore that someone populated with Plan 2.005's push or 2.009's import.

## Decisions

Proposed in this plan, for approval:

| Topic | Choice | Reason |
| --- | --- | --- |
| Where conflict copies go | `<root>/.metastore/remote/<store path>`, not beside the file | A copy beside the file, such as `x.remote.md`, would be read as a plan by `grep`, scripts and `check`; Dragonfly had to exclude them everywhere |
| A local deletion | Kept: pull does not re-create a file whose state entry exists; `pull <path>` does | Deleting is a local change like an edit; recovery after `git clean -fdx` still works because that also removes `.metastore/` |
| Fetching bodies | One `get` per document to write, eight at a time | Keeps the protocol small; a first pull of 1,000 documents takes seconds. A list-with-bodies capability can come later |
| Writing files | Temporary file in the same folder, then rename; parents created; empty folders below a store folder removed after a removal | No half-written document; no empty folders left behind |
| Symbolic links in a store folder | Never written through or removed; reported by `status` | The mirror owns plain files only |

## Design

### Resolving the mirror (`src/core/metastore/mirror/resolve.ts`)

```ts
export interface Mirror {
  root: string;                         // repository-relative, e.g. "docs"
  folders: string[];                    // store folders, root-relative, each ending "/"
  windows: Record<string, SyncWindow>;  // used by Plan 2.006
  /** References of the document folder that contains a store path, for content mapping. */
  mappingFor(storePath: string): ReferenceMapping;
  dir: string;                          // absolute <repo>/<root>/.metastore
}
export function resolveMirror(factory: Factory, config: MetastoreConfig): { mirror: Mirror; problems: Problem[] };
```

`folders` is `config.folders`, else every `documents` folder (Plan 2.001) whose path starts with `<root>/`, with that prefix removed. Problems, errors on `.factory/metafab.yaml` at the key's line: a `sync` key that is not a store folder, `Sync window "<k>" is not a store folder`, fix listing the folders. `runCheck` adds them after the configuration problems. `mappingFor` finds the `documents` entry whose folder contains `<root>/<storePath>` and returns its `references`, or none.

### Command context (`src/core/metastore/mirror/context.ts`)

Every metastore command except `login` and `logout` starts with one function, so the rules in [Command behaviour](../specs/metastore.md#command-behaviour) are enforced in one place:

```ts
export interface MirrorContext { root: string; factory: Factory; config: Config; mirror: Mirror; backend: MetastoreBackend; command: string; problems: Problem[] }
export async function openMirrorContext(cwd: string, env: NodeJS.ProcessEnv, command: string): Promise<MirrorContext>;
```

1. `findFactory(cwd)` and `loadFactory`; no factory is the existing discovery error.
2. `loadConfig`. Any configuration error (including the `metastore` rules) is exit 1 with every error listed; warnings are kept.
3. No `config.metastore`: exit 1, `No metastore is configured`, fix `Add a metastore section to .factory/metafab.yaml`.
4. `resolveMirror`; its errors are exit 1.
5. `openBackend`; its warnings join `problems`. The backend is not contacted here.

Each command returns a `CommandResult` whose `problems` include `ctx.problems`, so warnings show in text and in `--json`. Command results carry the documents they changed or listed (`written`, `updated`, `removed`, `kept`, `conflicts` for pull; the report for status; the version for show; the versions for log).

### Path arguments (`src/core/metastore/mirror/args.ts`)

`resolvePathArgs(args: string[], mirror: Mirror, cwd: string): { documents: string[]; folders: string[] }` accepts a repository path (relative to the repository root or to `cwd`), a store path, or a folder ending in `/`, and returns store paths. Anything outside the store folders is exit 1: `<arg> is not in a store folder`, fix `Store folders: <root>/<f>, …`.

### Working-tree files (`state.ts`, `index-file.ts`, `conflict-copies.ts`)

```ts
export interface StateEntry { version: number; hash: string; pinned?: true; remote?: number }   // remote: the conflict copy's version
export interface MirrorState { schema: 1; metastore: string; pulledAt?: string; documents: Record<string, StateEntry> }
export async function readState(mirror: Mirror, backendId: string): Promise<{ state: MirrorState; problems: Problem[] }>;
export async function writeState(mirror: Mirror, state: MirrorState): Promise<void>;          // temporary file and rename

export interface IndexEntry extends Omit<DocumentListItem, "path"> {}
export interface MirrorIndex { schema: 1; metastore: string; listedAt: string; documents: Record<string, IndexEntry> }
export async function readIndex(mirror: Mirror, backendId: string): Promise<{ index?: MirrorIndex; problems: Problem[] }>;
export async function writeIndex(mirror: Mirror, index: MirrorIndex): Promise<void>;

export async function writeConflictCopy(mirror: Mirror, version: DocumentVersion, bytes: Uint8Array): Promise<string>;  // returns the repository path
export async function removeConflictCopy(mirror: Mirror, storePath: string): Promise<void>;
```

For both files, the same rules apply to every command:

| File state | Result |
| --- | --- |
| Missing | Empty state, or no index; no problem |
| Another metastore's id | Empty state, or no index; no problem (the next write replaces it) |
| Not valid JSON, or the wrong shape | Empty state, or no index, with a warning `<file> is damaged and was ignored`, fix `It is rebuilt by the next metafab metastore pull` |

So `pull` rebuilds both; online `status` lists the metastore and treats every local file as unrecorded; `status --offline` with a damaged index reports only local changes and the warning.

Every command that writes `state.json` holds `<root>/.metastore/lock` (`acquireLock` with `waitMs: 0`), and the error names the other command.

### Scanning local files (`scan.ts`)

`scanMirror(mirror, root): Promise<Map<string, LocalFile>>` walks each store folder with `readdirTyped`, skipping names that start with `.`, and returns, per store path, `{ kind: "file" | "link" | "other", bytes? }`. Links and other entries are never read. `localHash(file, mapping)` uses `readDocument` and `contentHash` from Plan 2.002; a file that `readDocument` refuses (not UTF-8) gets `hash: undefined` and its problem.

### Git guard (`guard.ts`)

`trackedStoreFolders(root, mirror): Promise<string[]>` runs `git ls-files -z -- <root>/<f>…` once. Outside Git, or when `git` is not installed, it returns `[]`. `pull`, `push`, `mv`, `archive` and `restore` call `assertNotTracked`, which throws exit 1: `Git still tracks files in <folders>`, fix `Run metafab metastore import, then git rm -r --cached <folders>, and commit. See "Moving folders out of Git" in docs/specs/metastore.md`.

### Pull (`pull.ts`)

```ts
export interface PullOptions { paths?: string[]; all?: boolean; force?: boolean }
export interface PullResult {
  written: string[]; updated: string[]; removed: string[]; recorded: string[];
  kept: { path: string; reason: "modified" | "deleted" | "conflict" | "case" | "link" }[];
  conflicts: string[];          // repository paths of conflict copies written
  problems: Problem[];
}
export async function pull(ctx: MirrorContext, options: PullOptions): Promise<PullResult>;
```

`MirrorContext` comes from `openMirrorContext` (above). Steps:

1. `assertNotTracked`; take the lock; `readState`.
2. `backend.list({ archived: true })` once. Write the index from it (Plan 2.006 adds windows; here every active document is wanted).
3. `scanMirror`. For each wanted path (all active documents in the store folders, or only those under `options.paths`), apply the table in [Pull](../specs/metastore.md#pull). Fetch each version to write with `backend.get(path, listed.version)`, the version the list call returned, never the unversioned current one, so the files, the state and the index all describe one snapshot; a save that lands during the pull is picked up by the next one. `readBlob` for `file` documents checks the hash. Eight requests at a time.
4. A remote path whose folded form equals a different local path (`foldPath`) gets a conflict copy and `kept: case`. Before every write or removal, `safeTarget(repoRoot, repoPath)` `lstat`s each existing ancestor from `<root>` down to the file's folder, and the file itself: an ancestor that is a symbolic link or not a directory makes the document `kept: link` and nothing is written or removed below it; a link at the file's own path is `kept: link` too. Folders are created one level at a time with the same check, so nothing is ever written through a link.
5. For archived documents, and for state entries whose path is no longer listed: remove a clean local file and its entry; keep a modified one (`kept: modified`).
6. When the local file equals the remote content but the state has no entry, or the entry's hash differs only because the state was missing, record it.
7. A pull that brings a file up to date removes its conflict copy and clears `remote`.
8. Write the state with `pulledAt`; release the lock.

With `paths`, steps 3 to 7 cover only those documents and folders, a deleted file is written back, and other entries are untouched; the index is still rewritten whole. `force` replaces modified and deleted files in scope with the current version and removes their conflict copies.

### Status (`status.ts`)

`status(ctx, { offline }): Promise<StatusReport>` with `{ modified, new, deleted, behind, conflict, archived, links, tracked, outside: number }`. Online, it lists the metastore once (and does not write the index or state). With `offline` it uses the index and adds the note `Read from the index of <listedAt>; run without --offline for the current state`. Without an index, offline status reports only local changes. `outside` stays 0 until Plan 2.006.

### Commands

- `pull [<path>…] [--all] [--force] [--if-signed-in] [--if-new]`: `--all` is accepted and has no effect until Plan 2.006. `--if-signed-in` catches `metastore-unauthenticated` and `metastore-unreachable` and returns exit 0 with the summary `Metastore not pulled: <reason>. Run metafab metastore pull when you are signed in.` `--if-new` returns at once with `This working tree already has a mirror` when `state.json` exists. The summary lists counts, then each kept file and conflict copy with its fix (`Merge <copy> into <path>, then push with --resolved`). Exit 0, also when files were kept: keeping local work is the expected outcome.
- `status [--offline]`: one line per path, `M`, `A` (new), `D` (deleted), `B` (behind), `C` (conflict), `X` (archived), `L` (link), then the tracked-folder problem if any. Exit 0.
- `show <path> [--version <n>]`: `backend.get`; a missing path or version is exit 1, `<path> has no version <n>`. Text documents are written with `writeDocument` to standard output. A `file` document is written as bytes when standard output is not a terminal; in a terminal, exit 1 with `<path> is a file; redirect the output, such as > out.<ext>`. With `--json`, the result has the version without `body` and, for text, `text`.
- `log <path>`: `backend.versions`; one line per version: `v<n>  <savedAt date and time>  <savedBy.name>  <origin.branch or ->  <state if archived>  <message>`. Missing path: exit 1.

### Build (`src/core/build/agents.ts`, `plan.ts`)

`gitignoreBlockBody(agents, mirrorLines)`; `planBuild` computes `mirrorLines` with `resolveMirror` when `config.metastore` is set (`/<root>/<folder>` per store folder, then `/<root>/.metastore/`). A mirror resolution problem leaves the lines out and is reported by `check`, not by `build`.

### Edge cases

- **A second pull with nothing new** writes no file, and rewrites `index.json` and `state.json` only when their content changed.
- **Interrupted pull.** Files written before the interruption are complete (rename); their state entries are missing, so the next pull finds them equal and records them.
- **Windows and macOS case-insensitive file systems.** Rule 5 of [Paths](../specs/metastore.md#paths) means the metastore holds no two paths that differ only in case; a local file that does is kept and gets a conflict copy.
- **CRLF.** A file an editor saved with CRLF hashes equal to the stored LF version, so it is not modified.
- **No network.** `pull` exits 6, or 0 with `--if-signed-in`; `status --offline`, `show` and `log` need the backend except `status --offline`.
- **Store folder missing locally.** Created on the first write.

## Tests

All pull and status tests run twice through a helper, against the local backend and against the test server from Plan 2.003, on a temporary Git repository with a format 2 factory declaring `docs/plans/` with `references: [needs]`.

- Pull: a fresh mirror gets every document with LF and mapped references (`needs: [docs/plans/a.md]`); a second pull writes nothing (file mtimes unchanged); each row of the spec's table; an archived document with a clean file is removed and its empty folder too; `pull docs/plans/x.md` writes a deleted file back; `--force` replaces a modified file and removes its conflict copy; a `file` document's bytes are exact and a wrong hash from the backend is exit 6; a local link at a document's path is untouched and reported; a case variant (on every platform, using the folded comparison) gets a conflict copy; a missing `state.json` with equal files records them, and with a different file writes a conflict copy; a `state.json` for another metastore id is ignored; a damaged one warns; the lock held by another command is exit 1 naming it.
- Guard: a store folder with a tracked file makes `pull` exit 1 naming the folder; outside Git it pulls.
- Links (skipped on Windows): `docs/plans/sub` as a link to a folder outside the repository; a document under it is `kept: link`, and nothing is created at the link's target.
- Snapshot: a save between the list and the fetch (a test wrapper around the backend that applies a change after `list` returns) leaves the file, state and index at the listed version, and the next pull brings the newer one.
- Context: no factory; a factory with no `metastore` (exit 1 with the fix); an invalid `metastore` key (exit 1 listing it); a damaged credentials file's warning in `--json` `problems`; every command's `--json` result is one object with `exitCode`.
- Damaged files: a damaged `state.json` and a damaged `index.json` each give the warning, and pull rebuilds them.
- Flags: `--if-signed-in` with no token is exit 0 with the notice, against the test server; with an unreachable URL too; `--if-new` does nothing when `state.json` exists.
- Status: each mark; `--offline` with and without an index.
- `show`: current and `--version`; a `file` to a terminal (injected `tty: true`) is exit 1; JSON has `text`. `log`: lines in order with the origin branch.
- Build: `.gitignore` block with metastore lines for `agents: [claude]` and for `agents: []`; no lines without a metastore; a sync key that is not a store folder is a `check` error and the build still succeeds.
