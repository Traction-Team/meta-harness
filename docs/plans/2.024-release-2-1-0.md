# Plan 2.024: Release metafab 2.1.0

fab-basic cannot rename its workflows to plain files until a published Metafab reads them: 2.0.0 refuses format 3 with exit 4 at `import`. This plan releases `main` after Plans 2.022 and 2.023 as `2.1.0` under `latest`, with the release workflow from Plans 1.012 and 2.016, so [Plan 2.025](2.025-use-workflow-files.md) can depend on it.

## Specs

- [CLI: Installation](../specs/cli.md#installation), which Plan 2.022 already updated for format 3

This plan changes no spec beyond the `docs/specs/README.md` index.

## Decisions

| Topic | Choice | Reason |
| --- | --- | --- |
| Version | `2.1.0`, a minor | Workflow files and the `AGENTS.md` section add behaviour; format 1 and 2 factories still build. The new section changes every factory's generated block, which the release notes call out, but no source needs editing |
| What ships | `main` as it stands, including 2.020 if it has merged | The release workflow publishes `main`; nothing is held back |
| The store | Not in 2.1.0. It ships in a later minor | The roadmap's earlier "store as 2.1.0" note predates this work; the roadmap line is updated in this plan's landing commit |

## Design

- **Version.** `package.json` and `package-lock.json` go to `2.1.0`. `dist-tag.mjs` prints `latest` for it, so the tag `v2.1.0` publishes under `latest` with provenance after `npm run verify`.
- **README.** The factory layout in the quick start mentions `workflows/<name>.md`, and says only `SKILL.md` is installed as a skill. One paragraph under upgrading: after 2.1.0, the first `metafab build` adds a Workflows section to the root `AGENTS.md` block, so commit that change (or set `agents-md: { workflows: false }`); `check` and the CI recipe report the block stale until then. Format 3 needs 2.1.0.
- **Specs index.** `docs/specs/README.md` names format 3 beside 1 and 2.
- **Changelog.** This plan's landing commit adds the changelog entry, which says the same as the README paragraph.
- **Failure.** The workflow's `verify` job fails before `npm publish`: nothing is published; fix on `main`, delete the tag and push it again. A re-run after a successful publish fails on npm's duplicate version and changes nothing.
