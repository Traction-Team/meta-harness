# Plan 2.014: Build --out previews another environment and the metafab skill teaches environments

After Plan 2.013 a factory can say different things to different harnesses, but an author cannot see what a teammate on another harness receives without changing their own selection and rebuilding their own skills. This plan adds `metafab build --out <dir>`: it writes the compiled skills for any `--env` selection into a separate directory, with the `AGENTS.md` block beside them, and touches nothing else, so a person or an agent can read or diff it. The block is the committed root block, which is rendered for every value whatever the selection ([Root `AGENTS.md`](../specs/environments.md#root-agentsmd)), so it is the same in every preview; the skills are what differs. It also teaches agents to author environments: the built-in `metafab` skill gains an Environments section, and the format's workflow guidance stops recommending a separate tool-specific skill in favour of `when`, `switch` and partials.

## Decisions

| Topic | Choice | Reason |
| --- | --- | --- |
| Shared code | `desiredOutput` is factored out of `planBuild`; the preview never calls the repository scan, `applyBuild` or `syncGitHooks` | The preview is exactly what `build` would install, and cannot touch the repository |
| `<dir>` rules | Absent, or an empty directory; not a file; not inside `.factory/`, `.claude/skills/` or `.agents/skills/` after resolving links | Never overwrites; never leaves output where the next `build` finds an unowned entry (spec amended) |
| Exit codes | Non-empty `<dir>`: 5; a file, a forbidden location or an empty `--out`: 1 | Exit 5 already means "would overwrite output Metafab does not own" |
| `<dir>/AGENTS.md` | The whole marker block (`<!-- factory:start -->` to `<!-- factory:end -->`) and a trailing newline, rendered for every value, so it is byte for byte the block `build` writes to the root `AGENTS.md`, whatever `--env` says | The spec: the root block is selection-independent; the preview shows what a teammate actually receives |
| `agents: []` | The preview writes nothing and says so | It mirrors `build`, which writes no block and no skills for no targets |
| Built-in skill | Included in the preview when `metafab-skill` is on | It is part of what a teammate receives |
| Failure while writing | Files with the `wx` flag and directories with non-recursive `mkdir`, so `EEXIST` below `<dir>` is a conflict (exit 5); on any failure remove every file and directory this run created, deepest first; a `<dir>` that existed (empty) before the run stays; exit 1 for a write error | A half-written preview would mislead, and a directory the person made is not Metafab's to delete |
| Skill examples | Every directive example in the built-in skill is inside a fenced code block | Fenced lines are never directives, so the skill reads the same in every factory and format |

## Design

### Preview (`src/core/build/preview.ts`, new; `plan.ts`)

```ts
export interface DesiredOutput {
  /** Destination directory (".agents/skills", ".claude/skills") → skills, for the selected agents. */
  skills: Map<string, DesiredSkill[]>;
  /** The full AGENTS.md block, markers included, rendered for every value (never for the selection), or undefined when no target is selected. */
  agentsBlock?: string;
  errors: Problem[];
  warnings: Problem[];
}
export async function desiredOutput(factory: Factory, config: Config, cliVersion: string, selection: ResolvedSelection): Promise<DesiredOutput>;

export interface PreviewPlan { out: string; created: boolean; writes: BuildWrite[]; errors: Problem[]; conflicts: Problem[]; warnings: Problem[] }
export async function planPreview(factory: Factory, config: Config, cliVersion: string, out: string, options: PlanBuildOptions): Promise<PreviewPlan>;
export async function writePreview(plan: PreviewPlan): Promise<BuildChange[]>;
```

`planBuild` calls `desiredOutput` for its skills and block, so the two cannot differ. `planPreview`:

1. Resolves `out` against the command's working directory. An empty string: error, `--out needs a directory`.
2. `lstat(out)`: a file or a link to one, `--out <dir> is not a directory` (exit 1). A directory with any entry: conflict, `--out <dir> is not empty`, fix `Choose a new directory or empty it` (exit 5). Absent: `created: true`.
3. `canonical(p)`: the `realpath` of the nearest existing ancestor of `p` (`p` itself when it exists), joined with the remaining, not yet existing segments. `canonical(out)` is compared with `canonical(<root>/.factory)`, `canonical(<root>/.claude/skills)` and `canonical(<root>/.agents/skills)` using `isInside`, so a destination that does not exist yet, or a `.claude` that is a link, is compared on the same footing as `out`: `--out <dir> is inside <x>, where build would find it`, fix `Choose a directory outside .factory/ and the skill destinations` (exit 1). Inside the repository elsewhere is allowed.
4. `desiredOutput` errors stop the preview (exit 1) before anything is created.
5. Writes: `<dest>/<skill>/<path>` for each selected destination, with build's modes, and `AGENTS.md` with `agentsBlock + "\n"`. `agentsBlock` comes from `desiredOutput`, which renders `.factory/AGENTS.md` with `allValues(env)` for the preview exactly as for `build`; the selection only reaches the skills.

`writePreview` creates everything exclusively, so it never writes into an entry it did not make: each directory with `mkdir` without `recursive` (one level at a time), each file with `writeFile(path, data, { flag: "wx" })`. It records, in creation order, every directory and file it creates, and sets each file's mode (no-op on Windows). `EEXIST` on `out` itself or on any entry below it means something appeared after the preflight: that is a conflict, `<path> appeared while the preview was being written`, exit 5, and the run rolls back as below. `EEXIST` on a missing ancestor of `out` that is now a directory is not a conflict: another process made it, so the walk continues and does not record it. On a write error or a conflict it removes the recorded entries deepest first (files, then directories, longest path first), never an entry it did not create, so a `<dir>` that existed and was empty stays, empty, and an absent `<dir>` is gone with any parents the run made. Then it throws a MetafabError: exit 5 for the conflict, exit 1 and `Cannot write <path>` for a write error. A removal that itself fails adds one warning, `Could not remove <path>; remove it by hand`, and rollback goes on with the other entries; each directory above a path left behind is then not empty, so it is left too, with no warning of its own. The exit code stays that of the original failure. Removal goes through an injectable `remove` function so tests can make it fail.

### Command (`src/commands/build.ts`)

`out: { type: "string" }`. With `--out`, `runBuild` loads, resolves `--env` and calls `planPreview` and `writePreview` instead of `planBuild` and `applyBuild`. Text summary: one `+ <out>/<path>` line per file, then `Previewed <n> files in <out> for harness=amp, workspace=orb.` (each variable's selected values), or `Nothing to preview: agents is empty.` JSON: `{ ok, command: "build", exitCode, out, written: [paths relative to out, POSIX], env, problems }`; `changed` and `hooks` are absent, because nothing in the repository changed.

### The built-in skill (`resources/metafab-skill/SKILL.md`)

A new section, `## Write one factory for several environments`, after "Create workflows and skills", of about 40 lines, with every directive example fenced:

- When to use it: a team uses different harnesses or workspace tools, and a workflow would otherwise say "in X do this, in Y do that".
- Declare variables in `factory.yaml` (`format: 2`, `env`, value labels that say how an agent recognises where it is, for example `In Amp (AMP_THREAD_ID is set)`).
- Choose the tool: `when` for a few lines that apply to some environments; `switch` where every value needs its own text, because `check` then lists every switch to update when a value is added; `import` from `.factory/partials/` when several workflows share a procedure; a `skills:` entry when a whole skill applies only somewhere.
- Rules an agent must keep: descriptions and other frontmatter stay harness-neutral and contain no directives; directives are whole lines; blocks close in the same file; each branch must read correctly on its own because `build` removes text without renumbering.
- Selection: `metafab env` shows it; `metafab env set harness=opencode,claude` (or `--global`) changes it and rebuilds; setup scripts set `FACTORY_ENV_*`.
- Checking: `metafab check` validates every branch whatever the selection; `metafab build --env harness=amp --out /tmp/preview-amp` shows what another harness receives, without touching the repository.
- The root `AGENTS.md` block is rendered for every value, labelled, and is the same for everyone.

"Design a factory" gains one line: "If people work in different harnesses, declare `harness` in `env` before writing tool-specific steps."

The expected copies in `test/fixtures/build/mark4-like/expected/**/metafab/SKILL.md` are regenerated.

### Edge cases

- **Relative and Windows paths.** `--out ..\preview` resolves with `path.resolve` on Windows; summaries print paths with `/`.
- **`--out .`** in a non-empty repository: exit 5.
- **A link at `<dir>` to an empty directory outside the repository.** Allowed: the check uses the resolved target.
- **Second run with the same `<dir>`.** Exit 5: the preview never overwrites. The message suggests a new directory.
- **No Git, or not a Git repository.** The preview needs neither; selection falls back as Plan 2.011 says.
- **Format 1 factory.** `--out` works and shows today's output; `--env` still errors because nothing is declared.
- **`--json` without a terminal.** Nothing prompts.

## Tests

- Preview of a fixture with `harness` and a conditional skill: with `--env harness=amp` the Amp text only and the Amp-only skill present; with `--env harness=opencode` neither; `<dir>/AGENTS.md` is byte for byte the same for both selections and equals the root `AGENTS.md` block that `build` writes; only the selected destinations exist.
- The repository is unchanged byte for byte (installed skills, `AGENTS.md`, `CLAUDE.md`, `.gitignore`, `.gitattributes`, hooks directory), compared before and after.
- `<dir>`: absent (created, with parents); empty (used); non-empty (exit 5, untouched); a file (exit 1); `.factory/x`, `.claude/skills/x`, `.agents/skills/x` (exit 1); a link into `.factory/` (exit 1, skipped on Windows); `--out ""` (exit 1).
- A factory error (an unbalanced `when`) exits 1 and does not create `<dir>`.
- A mid-write failure, injected through a failing `writeFile` after some files are written: with an absent `<dir>` (and an absent parent), exit 1 and neither `<dir>` nor the parent exists; with a pre-existing empty `<dir>`, exit 1 and `<dir>` exists and is empty. A read-only parent (skipped on Windows and as root) exits 1 the same way.
- A failing removal during rollback: with an absent `<dir>`, inject a write failure on the third file and a removal failure on the first file, `<dir>/.agents/skills/a/SKILL.md`. The result is exit 1 with the write error and exactly one warning, `Could not remove <dir>/.agents/skills/a/SKILL.md; remove it by hand`. Left behind are exactly that file and its parents `<dir>/.agents/skills/a`, `<dir>/.agents/skills`, `<dir>/.agents` and `<dir>`; the second file and every other directory the run made are gone.
- A file that appears between preflight and write, injected by a test hook that creates `<dir>/AGENTS.md` (and, in a second case, `<dir>/.agents/`) after `planPreview` returns: exit 5 naming the path; the injected entry is left untouched; every entry the run created is removed; a pre-existing empty `<dir>` stays.
- Destinations canonicalised: with `.claude` a link to another directory, `--out` inside the link's target under `skills/` exits 1; with no `.agents/skills` yet, `--out .agents/skills/x` exits 1.
- `agents: []`: nothing written, the summary says so.
- `--json` shape: `out`, `written`, `env`, no `changed`.
- The installed `metafab` skill contains `## Write one factory for several environments`, and `directiveLines` on it, fence-aware, returns nothing.
- `metafab build --help` lists `--out <dir>`.
