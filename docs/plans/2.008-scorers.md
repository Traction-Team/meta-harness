# Plan 2.008: Scorers in `.factory/scorers/` give judges a prompt and record their results

`review-plan` and `review-branch` find defects, but nothing measures quality over time: whether plans are getting clearer, or whether a change to a workflow or a model made pull requests better. A scorer is a rubric with a fixed scale and named criteria that a judge, a model in a fresh session, applies to a subject, so its scores compare across plans, pull requests and months. This plan gives the reserved `scorers/` folder its meaning in format 2: each `.factory/scorers/<name>.md` is a scorer, validated by `metafab check` and shipped in fabs. `metafab scorer list` finds the scorers for a subject, `scorer prompt` prints exactly what a judge sees, and `scorer record` checks the judge's answer and records it as a score (Plan 2.007). How a workflow runs scorers is the factory's choice; this plan gives it the tools.

## Decisions

Proposed in this plan, for approval:

| Topic | Choice | Reason |
| --- | --- | --- |
| Shape | One Markdown file per scorer, not a skill directory | A judge gets only the prompt `scorer prompt` builds, never a skill list; a file keeps the rubric and its fields together |
| Where | The reserved `scorers/` folder, in format 2 | The format reserved it for this in version 1 |
| Score value | Weighted mean of whole-number criterion values, two decimal places | Criteria are what a judge can apply reliably; the weights are the factory's statement of what matters |
| Who checks the answer | `scorer record`, not the judge | A model that drifts from the format fails loudly instead of recording a wrong score |
| Rubric version | `git hash-object` of the scorer file, plus `run.dirty` when it has uncommitted changes | Scores from one rubric group together on any branch; an edited rubric starts a new series |

## Design

### Model and discovery (`src/core/factory/types.ts`, `discovery.ts`, `load.ts`)

```ts
export interface Scorer {
  name: string;
  file: string;                 // repository path, ".factory/scorers/<name>.md"
  description: string;
  subjects: ScorerSubject[];    // "document" | "pull-request" | "branch" | "commit" | "file" | "url"
  paths: string[];              // [] when absent
  scale: { min: number; max: number };
  criteria: { id: string; weight: number; question: string }[];
  body: string;                 // the rubric, after the frontmatter
  line: number;                 // 1, for problems about the whole file
}
```

`Factory` gains `scorers: Scorer[]`, empty in format 1. Discovery reads the entries of `.factory/scorers/` (not recursively) with `readdirTyped`; regular files ending in `.md` (case-insensitive) are scorers when `factoryYaml.format === 2`, except a file named `SKILL.md` in any letter case, which is never a scorer and stays rule 11 only. Skill directories inside are skills as before.

### Rule 15 (`src/core/scorers/parse.ts`, called from `load.ts`; message helpers in `validate.ts`)

`parseScorer(file, text): { scorer?: Scorer; problems: Problem[] }`, using `parseFrontmatter` from `src/util/frontmatter.ts` (a missing frontmatter is its existing error). Errors, each on the line of the field (or 1):

- unknown field: `Unknown field "<f>" in a scorer`, fix from `didYouMean` over the six fields
- missing field: `Scorer is missing "<f>"`
- `name` not equal to the file name without `.md`: `Scorer name "<n>" does not match its file name "<file>"`
- `name` breaks rule 5 or rule 10: the existing messages
- `description` or a `question` not a single line
- `subjects` empty, or naming an unknown kind: `Unknown subject "<s>"; use document, pull-request, branch, commit, file or url`
- a `paths` glob that is not relative, or given while `subjects` has neither `document` nor `file`: `"paths" applies only to document and file subjects`
- `scale`: not a mapping with whole-number `min` and `max`, or `min >= max`
- `criteria`: empty; an item not a mapping; an `id` that breaks the property name rule or repeats; `weight` not a positive finite number
- two scorers with the same name: impossible within one folder on a case-sensitive file system, but names equal ignoring case are an error on the later file

### Listing (`list.ts`)

`scorersFor(factory, subject?: InputSubject, root): Scorer[]`: all scorers without a subject; else those whose `subjects` include the subject's kind (`doc` → `document`, `pr` → `pull-request`, and so on) and, for `doc` and `file`, whose `paths` is empty or has a glob that matches the repository path (`<root>/<store path>` for a document) with `picomatch`. `scorer list [--subject <s>]` prints `<name>  <subjects>  <description>`; `--json` prints the scorers without `body`.

### Prompt (`prompt.ts`)

`buildPrompt(scorer, pinned: PinnedSubject, ctx): string` where `PinnedSubject` is the resolved subject from Plan 2.007's `resolveSubject` plus, for a document, its version. For a document without `@v<n>`, `scorer prompt` reads the current version from the backend (`backend.get(path)`) after the unsaved-changes check, so the prompt names an exact version.

The prompt is Markdown, in this order:

1. `# You are a judge` and two fixed paragraphs: the judge has no stake in the work and has not seen how it was made; it scores only against the rubric, must not reward length or confident tone, and must read the subject itself.
2. `## The subject` with the canonical subject and pin, and the commands to read it: a document, `metafab metastore show <store path> --version <n>`; a pull request, `gh pr view <n> --repo <owner>/<repo>` and `gh pr diff <n> --repo <owner>/<repo>`, with "The head commit was <sha> when this prompt was made; say so in the rationale if it has moved"; a branch, `git log --oneline <base>..<sha>` and `git diff <base>...<sha>`, where `<base>` is `git merge-base <default> <sha>` and `<default>` is `origin/HEAD`'s target, else `main`; a commit, `git show <sha>`; a file, `git show <sha>:<path>` with the pinned commit (the given one, else `HEAD`); a URL, `Open <url>`.
3. `## The rubric` with the scorer's body.
4. `## The criteria` with a table of `id`, `question` and `weight`, and the line `Score each criterion with a whole number from <min> to <max>.`
5. `## Your answer` with the contract: end the answer with exactly one fenced `json` block of the shape in [Running a scorer](../specs/metastore.md#running-a-scorer), one entry per criterion id in any order, each with a non-empty `note`, and a non-empty `rationale`.

`scorer prompt <name> --subject <s>` writes the prompt to standard output, and to standard error the line `Record the answer with: metafab scorer record <name> --subject <pinned input form> --scorer-version <hash> --result <file>`, where the pinned input form is `<store path>@v<n>`, `pr:<n>@<sha>`, `branch:<name>@<sha>`, `commit:<sha>`, `<file path>@<sha>` (Plan 2.007's file pin), or the URL, and `<hash>` is `git hash-object` of the scorer file at the time of the prompt. With `--json`, the result is `{ prompt, subject, scorerVersion, record }` and nothing goes to standard error. An unknown scorer is exit 1 with a did-you-mean; a scorer that does not apply to the subject is exit 1, `<name> does not score <kind> subjects` or `<path> does not match <name>'s paths`.

### Record (`record.ts`)

`parseResult(text): { criteria: { id; value; note }[]; rationale: string } | { problem: string }`: the last fenced block whose info string is `json` (case-insensitive), `JSON.parse`d. Problems, as one line each: `No json block found`, `The json block is not valid JSON: <message>`, `Criterion "<id>" is missing`, `Criterion "<id>" appears twice`, `Unknown criterion "<id>"`, `Criterion "<id>" must be a whole number from <min> to <max>`, `Criterion "<id>" needs a note`, `The answer needs a rationale`.

`scorer record <name> --subject <s> --result <file | -> [--scorer-version <hash>] [--round <n>] [--model <m>] [--dry-run]`:

1. When `--scorer-version` is given and differs from `git hash-object` of the scorer file now: exit 1, `<file> changed since the prompt was made (<given> → <now>)`, fix `Run metafab scorer prompt again and give the judge the new prompt`. Without the flag, the current file is used and the summary warns `No --scorer-version: the rubric was not checked against the prompt`.
2. Resolve the subject with `parseSubject` and `resolveSubject` (Plan 2.007), with the same unsaved-changes rule as `prompt`.
3. Read the result (`-` is standard input) and `parseResult`; a problem is exit 1 with the line, and `--json` puts it in `problems`.
4. `value` = Σ(value × weight) / Σ(weight), rounded half away from zero to two decimals. `criteria` keep their weights.
5. `scorerVersion` = `git hash-object <file>`; `run.dirty: true` when `git status --porcelain -- <file>` is non-empty. Without Git, both are left out with a warning.
6. `buildScore` with `name` = the scorer name, `scale`, `criteria`, `rationale`, `scorer` = the file path, `scorerVersion`, `model`, and `run.round`. With `--dry-run`, print the score and stop. Otherwise `recordScore`.

The summary: `Recorded <name> <value>/<max> on <subject>@<pin> (lowest: <criterion id> <value>)`.

### Edge cases

- **A long answer with several json blocks**, such as an example in the middle: the last block counts.
- **CRLF in the result file**: parsed after `toLF`.
- **No metastore**: `list` works; `prompt` and `record` for a non-document subject work with `--dry-run`; a document subject needs the metastore to pin it, and the error says so.
- **A fab with scorers imported into a repository**: they are factory files, so `import`, `update` and `diff` already handle them; they show in the review summary's "Other files" group.
- **`metafab build`**: unchanged; scorers are never installed.
