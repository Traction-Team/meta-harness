# Plan 1.029: Orb setup continues when the unshallow fetch fails

In every Amp orb started for PR #29 (the worker, two task threads, a fix thread, both review threads and the orchestrator's orb), `.agents/setup` failed at "Unshallow the clone": `git fetch --quiet --unshallow origin` exited 128 with "could not read Username for 'https://github.com'". The script runs under `set -euo pipefail`, so it stopped there, and `npm ci`, `npm run build` and `node dist/cli.js build` never ran; each thread ran them by hand. GitHub credentials reach the orb a moment later: the same fetch succeeded by hand in the same orb. After this pull request merges, the unshallow is the last step, a failed fetch prints a warning and setup exits 0, so every orb has its dependencies, `dist/` and factory skills. A clone that stays shallow only matters to the later base merge, and `build-plan` and `finish-plan` already unshallow before it.

## Decisions

| Topic | Choice | Reason |
| --- | --- | --- |
| How to survive the failure | Move "Unshallow the clone" to the end of the script, and on failure warn and continue. No retry | Setup runs for every orb, so its time matters. At the end, the fetch runs after `npm ci` and the build, which take long enough that the credentials have usually arrived, at no extra cost. A retry loop adds its whole backoff to every orb that has no credentials at all, and a failed unshallow is recoverable later, so a warning is enough |
| Exit status on failure | 0, with a `warning:` line on stderr that names the command to run by hand | The orb is usable; only the base merge needs a full clone, and the workflows handle that |
| No prompt | `GIT_TERMINAL_PROMPT=0` and `GCM_INTERACTIVE=never` on the fetch | The script must be non-interactive, as its header says. Without them, a terminal or a credential manager could wait for input |
| No hang | `git -c http.lowSpeedLimit=1000 -c http.lowSpeedTime=30`, and `timeout 120` when the `timeout` command exists | A stalled connection must not block setup. The orb image is Linux with coreutils; the `command -v timeout` check keeps the script working on a Mac, where `timeout` is absent |
| Automated test | None; a scripted proof in the pull request | `.agents/setup` is a repository-local Bash script, not part of the package. A vitest test would have to run Bash, skip on the Windows CI job, and stub `npm`. The proof below runs offline in a few seconds and covers the three cases |
| Repository | Here, not fab-basic | `.agents/setup` is repository-local. fab-basic's [process.md](../../.factory/docs/process.md) asks setup scripts to unshallow; this script still does, so no upstream change is needed |
| Retry before warning | No retry | Agreed with the person on 2026-11-15. Running the step last already gives the credentials time, and a retry adds seconds to orbs where the fetch fails anyway. Revisit if orb logs still show the warning often |

## Design

`.agents/setup` keeps its `step` helper and its `set -euo pipefail`. Only `unshallow()` and the order of the `step` calls change.

```bash
unshallow() {
  # build-plan and finish-plan merge the pull request's base, which fails in a shallow clone.
  # They also unshallow before that merge, so a failure here only warns: in a new orb the
  # GitHub credentials can arrive after setup starts.
  if [[ "$(git rev-parse --is-shallow-repository)" != "true" ]]; then
    echo "already a full clone"
    return
  fi
  local -a fetch=(git -c http.lowSpeedLimit=1000 -c http.lowSpeedTime=30 fetch --quiet --unshallow origin)
  if command -v timeout >/dev/null 2>&1; then
    fetch=(timeout 120 "${fetch[@]}")
  fi
  if ! GIT_TERMINAL_PROMPT=0 GCM_INTERACTIVE=never "${fetch[@]}"; then
    echo "warning: could not unshallow the clone (GitHub credentials may not be ready yet)." >&2
    echo "warning: build-plan and finish-plan unshallow before they merge the base; to do it now, run: git fetch --unshallow origin" >&2
  fi
}

step "Check Node" check_node
step "Install dependencies" npm ci --no-audit --no-fund
step "Build dist/" npm run build --silent
# The factory skills in .agents/skills/ (which Amp reads) are generated, not committed.
step "Install factory skills" node dist/cli.js build
step "Unshallow the clone" unshallow
```

The fetch runs as the condition of an `if`, so `set -e` does not stop the script when it fails. Git's own error line still prints above the warning, so the cause stays visible. The `# npm ci keeps package-lock.json untouched` comment moves to sit above the "Install dependencies" step it describes.

**Failure.** The orb sees git's error, the two `warning:` lines and `<== Unshallow the clone (Ns)`. Setup exits 0. The clone stays shallow and nothing else changes: an interrupted or failed `git fetch --unshallow` leaves the shallow file in place.

**Second run and stale snapshots.** The step checks `git rev-parse --is-shallow-repository` each time: a full clone prints "already a full clone", a shallow one tries again. The other steps are already idempotent.

**When the clone is still shallow later.** Two paths already handle it, and neither changes:

- `build-plan` step 8 (landing): "If `git rev-parse --is-shallow-repository` prints `true`, run `git fetch --unshallow origin` before the merge" ([SKILL.md](../../.factory/workflows/build-plan/SKILL.md), "First merge the pull request's base").
- `finish-plan` section D, step 1: the same check before it catches up with the base.

By then the credentials are present, because the worker has already pushed its draft pull request. The earlier "Catching up with the base" in `build-plan` (before steps 2 and 4) and the `stacked-prs` rebase do not unshallow. They work in a shallow clone because the branch was cut from the trunk tip the clone has, and `git fetch origin` brings new trunk commits on top of it, so the merge base is present. This plan does not change them; see Out of scope.

**Windows.** Not affected: the script runs only in Amp orbs (Linux). It keeps LF line endings.

## Tests

No test file. The builder runs this offline proof in a temporary directory and pastes the output. It stubs `npm` on `PATH` and gives the clone a stub `dist/cli.js`, so the real `node` runs `check_node` and the stub, and no network is used.

```bash
T=$(mktemp -d)
git init -q --bare "$T/origin.git"
git clone -q "$T/origin.git" "$T/seed"
for i in 1 2 3; do git -C "$T/seed" commit -q --allow-empty -m "c$i"; done
git -C "$T/seed" push -q origin HEAD
git clone -q --depth 1 "file://$T/origin.git" "$T/clone"
mkdir -p "$T/clone/.agents" "$T/clone/dist" "$T/bin"
cp .agents/setup "$T/clone/.agents/setup"
echo 'console.log("stub metafab build")' > "$T/clone/dist/cli.js"
printf '#!/bin/sh\necho "stub npm $*"\n' > "$T/bin/npm" && chmod +x "$T/bin/npm"

# 1. origin cannot be reached (refused at once, no network): warns, exits 0, later steps ran
git -C "$T/clone" remote set-url origin http://127.0.0.1:9/none.git
PATH="$T/bin:$PATH" bash "$T/clone/.agents/setup"; echo "exit $?"
git -C "$T/clone" rev-parse --is-shallow-repository      # true

# 2. origin reachable: unshallows
git -C "$T/clone" remote set-url origin "file://$T/origin.git"
PATH="$T/bin:$PATH" bash "$T/clone/.agents/setup"; echo "exit $?"
git -C "$T/clone" rev-parse --is-shallow-repository      # false

# 3. second run: "already a full clone"
PATH="$T/bin:$PATH" bash "$T/clone/.agents/setup"; echo "exit $?"
```

Expected: case 1 prints git's error, both `warning:` lines, `stub npm ci ...`, `stub npm run build --silent` and `stub metafab build`, then `exit 0`. Cases 2 and 3 exit 0 with no warning, and case 3 prints "already a full clone". The missing-credentials prompt itself cannot be reproduced offline; the by-hand check is the next fresh Amp orb's setup log.
