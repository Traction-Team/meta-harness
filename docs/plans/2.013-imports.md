# Plan 2.013: Factory Markdown imports shared partials

After Plan 2.012 every workflow that needs a harness-specific procedure (how to start a sub-agent, how to start a worker) carries its own `switch`, so the same variants are written several times and drift. This plan adds `<!-- factory:import <path> -->`: the line is replaced by the body of another Markdown file in `.factory/`, with that file's directives rendered in the importing file's context. One **partial**, by convention in `.factory/partials/`, holds each harness's version of a procedure side by side, and every workflow and `.factory/AGENTS.md` imports it. `check` validates every import, including those inside blocks the selection removes.

### Spec edits this plan makes

**`factory-format.md`, Directory layout.** Add `partials/*                  Markdown that skills and AGENTS.md import (a convention, not a reserved name; see Environments)` after `scripts/*`.

**`factory-format.md`, Validation.** Rule 14's "rules 1 to 4 and 6" becomes "rules 1 to 6", and its list gains "every import resolves inside `.factory/` without a loop".

**`building.md`, Compiled skills.** Step 3 becomes "In a format 2 factory, render every `.md` file, and `SKILL.md` below its frontmatter, for the [selection](environments.md#rendering), replacing each [import](environments.md#import) with the imported body."

**`sharing.md`, Importing a fab: Fab validation rejects.** Add "In a format 2 fab, a directive, condition, switch or import that breaks [Environments: Validation](environments.md#validation)". (The rule already applies through `loadFactory` since Plan 2.012; this names it.)

## Decisions

Agreed with the person:

| Topic | Choice | Reason |
| --- | --- | --- |
| Keyword | `import`, not `include` | Matches the rest of the directive vocabulary and reads as text inclusion, not a file copy |
| Where imports are written | An inline comment line, not a frontmatter field | The text lands where the line is; frontmatter stays a plain Agent Skill |
| Partials | Any `.md` file in `.factory/`; `.factory/partials/` by convention, not reserved | No configurable layout and no new reserved name |

Proposed in this plan, for approval:

| Topic | Choice | Reason |
| --- | --- | --- |
| Indentation | The imported body is inserted unchanged; it is not re-indented to the directive's indentation | The spec says "unchanged"; a partial meant for a list item is written indented |
| Trailing newline | One trailing newline of the imported body is dropped, so the import replaces exactly one line | No blank line appears just because the partial ends with a newline |
| BOM | Removed from an imported file | A BOM in the middle of a file is a stray character |
| Path rules | Exactly the spec's: a relative, `/`-separated `.md` path that resolves inside `.factory/` after following links. No extra rule for spaces, dot directories or `.factory/README.md` | The spec is the acceptance standard; an import of a file a fab does not carry already fails in that fab's validation as a missing file |
| The path argument | The comment text after `import`, trimmed, so it may contain spaces | No quoting syntax is needed |
| Symbolic links | Allowed for the file and for any parent directory, as long as each resolves inside `.factory/` | Matches how `build` treats links inside a skill |
| Letter case | The path must match the names on disk exactly, checked with `readdir`, on every file system | A path that works on macOS must not break on Linux CI |
| Read error wording | `Import "<p>" cannot be read`, not `Cannot read ...` | `dedupeReadErrors` keeps one `Cannot read` problem per file; two unreadable imports in one importer must both show |

## Design

### Resolving an import (`src/core/env/imports.ts`, new)

```ts
export interface ImportCache {
  factoryDir: string;               // absolute .factory, native separators
  factoryReal?: string;             // realpath of .factory, computed once
  files: Map<string, LoadedImport>; // by realpath: bytes, body and frontmatter problems only, never a path to resolve from
}
export interface LoadedImport {
  file: string;                     // repository-relative POSIX path, such as .factory/partials/sub-agents.md
  text: string;                     // the body, frontmatter removed
  firstLine: number;                // line of the body's first line in the file
  problems: Problem[];              // the imported file's own problems, such as a directive in its frontmatter (spec Validation rule 6)
}
/** Pure: path rules 1 to 5 on factory-relative POSIX paths. No file system access. */
export function importTarget(
  from: string,                      // factory-relative POSIX path of the importing file, such as workflows/build-plan/SKILL.md
  argument: string,
): { ok: true; target: string } | { ok: false; message: string; fix: string };   // target: factory-relative POSIX, such as partials/sub-agents.md
export function createImportCache(factoryDir: string): ImportCache;
export async function resolveImport(
  from: string,                      // factory-relative POSIX path of the importing file
  argument: string,
  cache: ImportCache,
): Promise<{ ok: true; real: string; loaded: LoadedImport } | { ok: false; message: string; fix: string }>;
```

Validation works only on factory-relative POSIX paths: the importing file is named as `workflows/build-plan/SKILL.md` or `AGENTS.md`, never as an absolute native path, so rules 1 to 5 give the same answer on every platform. File system access converts once, with `path.resolve(cache.factoryDir, ...target.split("/"))`, and uses native paths from there on.

Checks, in order; each failure is an error on the directive's line, in the importing file. Rules 1 to 5 are `importTarget`:

1. The argument is the comment text after `import`, trimmed; it may contain spaces. Empty: `factory:import needs a path`.
2. Absolute (`/x.md`, `C:/x.md`, `C:\x.md`, `\\server\x.md`): `Import path "<p>" must be relative to this file`.
3. A `\`: `Import path "<p>" must use /`.
4. Extension, lowercased, not `.md`: `Import path "<p>" must name a .md file`.
5. `path.posix.normalize(path.posix.dirname(from) + "/" + p)` (which also folds `a//b` and `./`) is `..` or starts with `../`: `Import "<p>" leaves .factory/`.
6. Segment by segment, from `.factory/` to the target, before the file is read: `readdir` the current directory (native, `path.resolve`) and look for the next segment by exact name. No exact match but one that differs only in case: `Import "<p>" differs in letter case from "<actual>"`, fix `Write "<actual>"`. No match at all: `Import "<p>" does not exist`. When the matched entry is a symbolic link, `realpath` it and check it with `isInside` (exported from `skill.ts`) against `realpath(.factory)`: outside is `Import "<p>" resolves outside .factory/`; inside, the walk continues by listing the link's target, so a symlinked parent directory inside `.factory/` is allowed. A dangling link is `does not exist`. Because the walk reads directory listings instead of opening the path, a wrong-case path gives the same error on a case-insensitive file system (macOS, Windows) as on a case-sensitive one (Linux), never a successful read.
7. The final entry, after links, is a directory: `Import "<p>" is a directory`.
8. `EACCES` or another read error, of a listing in step 6 or of the file: `Import "<p>" cannot be read`, fix `Check its permissions`.
9. `textContent` returns undefined (a NUL or invalid UTF-8): `Import "<p>" is not a UTF-8 text file`.
10. After removing a BOM and `toLF`: when the text starts with `---\n`, the frontmatter up to the next `---` line is removed and `firstLine` is the line after it; with no closing line, `Import "<p>" has unterminated frontmatter`.

The cache key is the `realpath` of the final file, and the cache holds only what does not depend on the route: the decoded body, `firstLine`, and the frontmatter problems. `resolveImport` returns, beside the cached entry, the **route path**: the lexical, factory-relative target from rule 5, such as `shared/a/x.md`, through whichever links it passed. Expansion uses the route path, never the realpath, as the imported file's own path: its nested imports resolve relative to `path.posix.dirname(route)`, exactly as a person reading the directive would expect, and its block and import problems name the route path. Problems that come from the file's bytes alone (frontmatter directives, unterminated frontmatter) name the file once, by its real path relative to `.factory/`. The loop check (`chain`) still compares realpaths, so a loop through two aliases of one file is still a loop.

`resolveImport` also checks the removed frontmatter with `directiveLines`: each directive line in it is a spec Validation rule 6 error, `Directives are not allowed in frontmatter`, on that line in the imported file, returned in `LoadedImport.problems`. The parser adds `loaded.problems` to the document's problems wherever the file is imported, and `environmentProblems` deduplicates them, so a partial with a bad frontmatter is reported once.

A loaded file is cached by `realpath`, with its problems, so a partial imported by ten workflows is read once per cache.

### Expanding imports (`src/core/env/directives.ts`, `render.ts`, `validate.ts`)

- `Node` gains `{ kind: "import"; line: number; path: string; file?: string; children: Node[] }`.
- `parseMarkdown` becomes `async` and takes `ImportCache`, the factory-relative POSIX route path of the file (for an imported file, the route through which it was imported), and `chain: readonly string[]` (realpaths being expanded). An `import` line resolves through `resolveImport`; the imported body is parsed as its own document (block balance, switches and fences are per file, spec rule 3), and its nodes become the import node's `children`. Rendering passes the enclosing conditions of the import line into the imported nodes, so a block in a partial is classified together with the conditions around the import.
- A realpath already in `chain` is `Import cycle: <a> → <b> → <a>` (repository-relative paths, in order), on the directive line that closes the loop; that import gets no children. A diamond (two imports of one file, no loop) is fine.
- The cross-file 1024-combination check (Plan 2.012) runs in `environmentProblems`, in one pass over each expanded document, the same pass that collects problems: it walks the tree with a stack of enclosing conditions and carries that stack into an import node's children. Each file's own parse already checks its blocks against its own enclosing conditions; this pass adds only what an import contributes. A block in an imported file whose variables, together with the stack carried in from the importer, span more than 1024 combinations is reported once, on the import directive's file and line in the importing file: `Condition on line <l> of <partial> spans too many combinations here: <n> over <variables>; the limit is 1024`, fix `Import it outside the enclosing blocks, or split the condition`. Rendering never meets such a document, because the error stops the build.
- Imports are expanded wherever they sit, including inside `when` blocks and `case` branches, so `check` validates them all (spec rule 5).
- `renderDocument` writes an import node's children with the current enclosing conditions, with no label of its own; inside a removed block nothing is written.
- Problems inside an imported file name that file and its own line numbers. A partial imported by several files reports each of its problems once: `environmentProblems` deduplicates by file, line and message.
- `.factory/AGENTS.md` imports resolve from `.factory/`. Imports in its text are rendered with every value, like the rest of it.

### Build (`src/core/build/skill.ts`, `plan.ts`)

`CompileSkillOptions.render` becomes `(file) => Promise<string>`. `planBuild` creates one `ImportCache` per run, shared by every skill and the standing instructions. A partial inside a skill directory is both installed as that skill's own file (rendered for the selection as a standalone document) and inserted wherever it is imported.

### Edge cases

- **Imported file imports its importer's sibling.** Paths are always relative to the route path of the file that holds the directive, also inside a partial, so a partial reached through a symlinked directory resolves its own imports from that directory.
- **A partial that is also a skill's `SKILL.md`.** Allowed; its frontmatter is removed, so the importer gets only the body.
- **Empty partial, or frontmatter only.** Inserts nothing.
- **Deep nesting.** Bounded by the loop check; no depth limit.
- **Windows.** Paths in directives use `/`. Validation joins them with `path.posix` against the importer's factory-relative path, and only the file system steps convert to native paths with `path.resolve`. A `\` in a directive is an error on every platform.
- **Case-insensitive file systems.** The `readdir` walk runs before any `realpath` or read, so `Partials/X.md` is the case-mismatch error on macOS, Windows and Linux alike.
- **Second run.** The cache lives for one `planBuild` or one `loadFactory`, so an edited partial is always reread.
- **Format 1.** `import` lines are text, with the same one-per-file warning as other directives.
- **Publish.** `publish.exclude` that removes an imported partial makes the staged validation fail with exit 4 and the `does not exist` error.

## Tests

- A workflow imports `../../partials/sub-agents.md`, whose `switch env.harness` gives each harness's text: the installed `SKILL.md` has only the selected text; with two values, both labelled; the partial's frontmatter is gone; no blank line is added.
- `.factory/AGENTS.md` imports the same partial: the root block has every case, labelled, for every selection.
- Nested: a partial imports another; a loop of two and of three files gives one error with the chain, on the right line; a diamond works.
- Each path rule in the list, on the directive's line: an empty path, `/abs.md`, `C:/x.md`, `a\\b.md`, `x.txt`, `../../../outside.md` from `.factory/workflows/x/`, a file symlink out of `.factory/` (skipped on Windows), `Partials/x.md` for `partials/x.md`, a missing file, a directory, an unreadable file (skipped on Windows and as root), a file with a NUL byte, unterminated frontmatter.
- `importTarget`, pure, with Windows-style inputs on every platform: `C:\x.md` and `\\server\x.md` are absolute, `..\partials\x.md` must use `/`, `workflows/a/SKILL.md` with `../../partials/x.md` gives `partials/x.md`, and with `../../../x.md` leaves `.factory/`; none of these tests touches the disk.
- Case, on a temporary directory: on Linux CI, where it is case-sensitive, `Partials/x.md` and `partials/X.md` for `partials/x.md` give the case-mismatch error naming the actual spelling, and `partials/y.md` gives `does not exist`. The same test runs unchanged on macOS and Windows CI, whose default file systems are case-insensitive, and must give the same errors, which proves no read succeeds before the `readdir` walk.
- A directive line inside an imported partial's frontmatter is a spec Validation rule 6 error on that line in the partial, reported once although two workflows import it; the partial's body is still inserted.
- Allowed by the spec, so no error: `partials/my notes.md` (spaces in the argument), `.drafts/x.md` (a dot directory), `a//b.md` and `./x.md` (normalised), and `README.md` from `.factory/AGENTS.md`.
- Symlinked parents (skipped on Windows): `.factory/shared` a link to `.factory/partials`, imported as `shared/x.md`, is inserted; `.factory/ext` a link to a directory outside `.factory/`, imported as `ext/x.md`, is `resolves outside .factory/` on the directive line, and nothing outside is read.
- Aliases (skipped on Windows): one real file `.factory/real/x.md` containing `<!-- factory:import ../n.md -->`, reached through two in-factory directory links, `.factory/a/link -> ../real` and `.factory/b/link -> ../real`; `.factory/a/n.md` and `.factory/b/n.md` hold different text. A workflow importing `../../a/link/x.md` gets `a/n.md`'s text and one importing `../../b/link/x.md` gets `b/n.md`'s; `x.md` is read from disk once (a spy on `readFile`); with `.factory/b/n.md` missing, the error names `b/link/x.md` and its line, and the `a` route still works.
- Combinations across an import: a partial with a `when` naming six two-value variables, imported inside a `when` naming five others, gives one error on the import directive's line in the importer, naming the partial's line; the same partial imported at top level is fine.
- An import inside a removed `when` is not inserted, and a missing target there is still an error.
- Two unreadable imports in one file give two problems.
- A partial in a skill directory is installed as a file, rendered, and is inserted into another skill.
- A partial with an unbalanced `when` reports the partial's file and line once, though three workflows import it.
- `import` of a fab whose workflow imports a missing partial exits 4; `publish --dry-run` with `publish.exclude: [partials/x.md]` exits 4.
- Format 1: an import line is copied as text, with one warning.
