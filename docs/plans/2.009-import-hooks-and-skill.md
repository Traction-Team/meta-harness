# Plan 2.009: `metastore import` moves folders out of Git, new worktrees pull the mirror, and the metafab skill teaches the metastore

This plan finishes the version 2 metastore for teams that already keep their documents in Git. `metafab metastore import [--ref <ref>] [--dry-run]` copies every file Git tracks in the store folders at a ref into the metastore, re-runnably, and never overwrites a change someone saved in the metastore that Git does not have. The summary then gives the exact `git rm -r --cached` command and the commit to make, because Metafab never stages or commits. With `git-hooks: true`, the `post-checkout` hook also fills a new worktree's mirror. The built-in `metafab` skill gains a Metastore section, so every agent knows to pull before deciding, push after a change that deserves a version, resolve conflicts, and run scorers. After it merges, version 2 is complete and ready to release.

## Decisions

Proposed in this plan, for approval:

| Topic | Choice | Reason |
| --- | --- | --- |
| What import compares | Content hashes in the stored form, against the current version, and against every version of the path in Git history at the ref | The Dragonfly rule: update only what Git already knew, so an edit saved in the metastore is never lost |
| Atomicity | Batches within the backend's limits, re-runnable | Thousands of files exceed one request; a rerun finds the saved ones `unchanged` |
| Untracking | Printed, never run | Metafab never stages or commits (CLI rule 3) |
| Hook | `post-checkout` only, with `--if-new` | `git worktree add` fires it; branch switches and merges do not change the mirror |
| Skill | One new section in the built-in skill, in this plan | One plan owns the skill text and its fixture copies |

## Design

### Import (`src/core/metastore/import-git.ts`)

```ts
export type ImportOutcome = "created" | "updated" | "unchanged" | "diverged" | "archived" | "refused";
export interface ImportResult { path: string; outcome: ImportOutcome; version?: number; reason?: string }
export async function importFromGit(ctx: MirrorContext, options: { ref: string; dryRun: boolean }): Promise<{ results: ImportResult[]; commit: string; stopped?: string }>;
```

1. `git rev-parse --verify <ref>^{commit}`; failure is exit 1, `<ref> is not a commit`, fix `Run git fetch, or name a branch, tag or commit`.
2. `git ls-tree -r -z --full-tree <commit> -- <root>/<folder>…` lists blob ids and modes per path; symbolic links (mode 120000) and submodules are `refused` (`not a regular file`). Paths below a folder whose name starts with `.` are skipped.
3. `backend.list({ archived: true })` once.
4. For each file: `git cat-file blob <id>` for the bytes; `readDocument` with the folder's mapping; `storePathProblem`; the limits from `info()`. Then, per document folder, `documentProblemsFor(factory, folder, documents, { indexed, focus })` with `documents` = every file under the folder at the ref (so the folder's `match` decides which get schema checks), `indexed` = each active document in the metastore under that folder whose path is not among the Git files, by repository path, with its stored properties mapped back to repository form, so a `unique` value only the metastore holds still collides, and `focus` = all the Git files. Any error makes a file `refused` with its first problem. Per file: no document → `created`, base 0. Archived → `archived`. Active with an equal hash (`backend.get` for the current content) → `unchanged`. Otherwise, when the current version's hash equals the hash of the path's content at any commit in `git log --format=%H <commit> -- <path>` (each distinct blob read once) → `updated` with the current version as base; else `diverged`, with `reason: "v<n> saved <date> by <name> is not in Git history"`.
5. Unless `dryRun`, send `created` and `updated` files in path order, in batches within `limits.changes` and `limits.requestBytes`, each with `putBlobs` first, the message `imported from git <first 7 of commit>`, and an origin from `captureOrigin` with `commit` replaced by the ref's commit, `branch` by the ref's branch name when `<ref>` names one (`git rev-parse --abbrev-ref`), else `null`, and `dirty: false`. A `conflict` or `invalid` outcome stops the run: earlier batches stay saved, and `stopped` explains it (`The metastore changed during the import; run it again`). Each file's `version` comes from the results.
6. Import never reads or writes the mirror, its state file or its index, and it does not run `assertNotTracked`: it is the command for tracked folders.

### Command (`src/commands/metastore/import.ts`)

`import [--ref <ref>] [--dry-run]`, `ref` defaulting to `HEAD`. Output: one line per file that is not `unchanged` (`<outcome>  <repo path>  <reason>`), then the counts. When it saved or would save anything and the folders are still tracked, it ends with the next steps:

```text
Next:
  git rm -r --cached docs/plans/ docs/intake/
  git commit -m "chore: move docs/plans/ and docs/intake/ to the metastore" -- .gitignore .factory/metafab.yaml docs/plans/ docs/intake/
  metafab metastore pull
```

Exit 1 when any file is `refused` or `diverged`, or the run stopped; else 0. `--json` returns the results, the commit and `stopped`.

### Hook (`src/core/hooks/script.ts`, `sync.ts`)

`hookScript(hook, factoryRelDir, cliVersion, options: { pullMirror: boolean })`. When `hook === "post-checkout"` and `pullMirror`, the script, after the build block and before `exit 0`, adds:

```sh
if [ -x node_modules/.bin/metafab ]; then node_modules/.bin/metafab metastore pull --if-signed-in --if-new
elif command -v metafab >/dev/null 2>&1; then metafab metastore pull --if-signed-in --if-new
else npx --yes @seasb/metafab@<version> metastore pull --if-signed-in --if-new
fi || echo "metafab: the metastore mirror was not pulled. Run metafab metastore pull." >&2
```

`syncGitHooks` passes `pullMirror: config.metastore !== undefined`. A change to `metastore` therefore rewrites the owned `post-checkout` hook on the next build, which the existing ownership rules already handle. The other hooks are unchanged.

`hookCommand(factoryRelDir, cliVersion, options: { hook: HookName; pullMirror: boolean })`: for `post-checkout` with `pullMirror`, the one-line command appends `; <the same CLI lookup> metastore pull --if-signed-in --if-new` inside its parentheses, before `|| true`. `syncGitHooks` uses it for both warnings that print a line to add by hand, the hook Metafab does not own (rule 2) and `core.hooksPath` (rule 3), so both name the pull for `post-checkout`.

### Built-in skill (`resources/metafab-skill/SKILL.md`)

A new `## Use the metastore` section after "Check and resolve problems", at most about 40 lines:

- How to tell whether this repository has a metastore (`metastore` in `.factory/metafab.yaml`) and which folders are store folders (`metafab metastore status`).
- Store folders are a mirror: never `git add` them. Edit files there as usual.
- Pull before a decision that depends on current documents (choosing work, reading a plan someone else may have changed): `metafab metastore pull`, or `pull <path>` for one document.
- `grep` sees only the sync windows; `metafab metastore ls <folder> --where key=value` lists everything, then `pull <path>`.
- Save with `metafab metastore push <paths> -m "<what changed>"` when a change deserves a version, as you would commit.
- On a conflict: read the copy push names, merge it into the file, `push --resolved`.
- Exit 6 means the person must sign in or check the network: ask them to run `metafab metastore login` in their own terminal; never ask for the token.
- Scores: `metafab scorer list --subject <s>`, run each scorer's `prompt` in a fresh sub-agent that sees nothing else, save its whole answer, `metafab scorer record`. Show the person the scores; do not treat them as a gate unless the factory says so.
- Moving existing folders: `metafab metastore import`, then the printed Git commands, made by the person or in a reviewed commit.

The expected copies under `test/fixtures/**/metafab/SKILL.md` change with it.

### Edge cases

- **Re-running import after a partial run** finds saved files `unchanged` and continues.
- **A branch cut before the move** runs `metafab metastore import --ref <branch>` before it merges `main`; its edits are then in the metastore, and it resolves Git's modify/delete conflicts by taking the deletion. The skill says so.
- **A large repository history.** Each distinct blob of a path is read once; paths with no current document need no history.
- **No Git.** `import` exits 1, `metafab metastore import needs a Git repository`.
- **Windows.** `git ls-tree -z` paths are POSIX; the hook stays POSIX `sh`, which Git for Windows runs.

## Tests

- Import, against the local backend and the test server, in a temporary repository with `docs/plans/` and `docs/intake/` committed over three commits: `--dry-run` reports `created` and sends nothing; a real run saves with the message and origin commit; a second run is all `unchanged`; a plan edited in a new commit is `updated` with the right base; a plan saved in the metastore with content Git never had is `diverged` and untouched; an archived document is reported; a plan that breaks its schema and a symbolic link are `refused`; a test server limit of 2 changes per request gives batches of 2 and a fault on the second batch stops the run with the first saved, and a rerun finishes; `--ref` with a branch sets `origin.branch`; an unknown ref is exit 1.
- The end-to-end move: after import, `git rm -r --cached`, a commit and `pull`, `status` is clean and every file is recorded.
- Hooks: `hookScript("post-checkout", …, { pullMirror: true })` text pinned by snapshot; `post-merge` unchanged; `syncGitHooks` rewrites `post-checkout` when `metastore` is added and again when it is removed; the pull line runs after the build line; with a metastore, the warning for an unowned `post-checkout` and the `core.hooksPath` warning both contain `metastore pull --if-signed-in --if-new`, and the `post-merge` warnings do not.
- Import rule set: a tracked `notes.txt` under a `match: "*.md"` folder is imported without a schema check; a Git plan whose `code` equals that of a plan only the metastore holds is `refused`.
- Skill, in `test/core/build/`: the installed built-in copy matches `resources/metafab-skill/SKILL.md` with its generated comment, and contains `## Use the metastore`.
