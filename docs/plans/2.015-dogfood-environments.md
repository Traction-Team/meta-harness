# Plan 2.015: The factory gives each harness and workspace only its own instructions

PR #25 (`chore/orb-setup`) taught this repository's workflows a second runtime, and Plan 1.024 carries that Amp flow into fab-basic beside the Orca and OpenCode flow, as hand-written variants: "in Amp, do this; with Orca and OpenCode, do that". Every agent reads every variant. This plan applies [Environments](../specs/environments.md) to the fab: fab-basic 0.2.0 declares `harness` (`opencode`, `claude`, `amp`) and `workspace` (`orca`, `orb`, `worktree`), keeps each procedure once in a partial with one `switch`, and makes every description harness-neutral. This repository then takes it with `metafab update`, pins the prerelease CLI that reads format 2, and has `.agents/setup` record the Amp and orb selection in each new orb's Git config before it builds. An Amp worker then reads only the Amp procedure, an OpenCode worker only the OpenCode one, and a Claude Code session only its own.

The work is in two parts. **Prerequisite A** happens outside this pull request (a prerelease of this package, and a release of fab-basic in its own repository) and its proof goes in this pull request's body. **Part B** is this repository's pull request.

> **Build order (approved 2026-11-15).** Build against the unreleased work first, so the person can evaluate the whole environments stack before anything is published. This plan stacks on Plan 2.016's branch. A2 is built on a fab-basic branch with a draft pull request there, and checked with the CLI from this stacked branch; no tag and no release. Part B imports fab-basic from that branch and runs `node dist/cli.js` from this checkout; B1's pin waits. The pull request stays a draft until 2.016 has merged, `v2.0.0-next.1` is on npm and fab-basic `v0.2.0` is tagged; then B1 pins `2.0.0-next.1`, B2 updates to `^0.2.0`, and the proofs are rerun.

## Design

### Prerequisite A: outside this pull request

**A1. Prerelease `@seasb/metafab@2.0.0-next.1`.** Plan 1.012's `.github/workflows/release.yml` runs `npm publish` on a `v*` tag with no `--tag`. That does not support a dist-tag: npm 11 refuses to publish a prerelease version without `--tag`, and an older npm would move `latest` to the prerelease. [Plan 2.016](2.016-prerelease-next.md) fixes that: the workflow publishes a version with a `-` under `next` and any other under `latest`, and the version becomes `2.0.0-next.1`. After it merges, tag `v2.0.0-next.1`. Proof for this PR's body: `npm view @seasb/metafab dist-tags` shows `next: 2.0.0-next.1` and `latest` still `1.x`, and `npm view @seasb/metafab@2.0.0-next.1` shows provenance.

**A2. fab-basic 0.2.0, in `github:Traction-Team/fab-basic`.**

`.factory/factory.yaml` gets `format: 2` and:

```yaml
env:
  harness:
    description: The agent tool that runs the workflows
    values:
      opencode: { label: In OpenCode (OPENCODE=1 is set) }
      claude:   { label: In Claude Code (CLAUDECODE=1 is set) }
      amp:      { label: In Amp (AMP_THREAD_ID is set) }
  workspace:
    description: Where start-plan gives each plan's worker its own checkout
    values:
      orca:     { label: With Orca worktrees }
      orb:      { label: In Amp orbs (workers start with create_thread) }
      worktree: { label: With plain git worktrees }
```

`requires` gains three entries, `path: .claude/agents/agent-coding.md`, `agent-review.md` and `agent-planning.md`, with templates in `.factory/templates/setup/claude-agents/` and the description "Defines the <name> sub-agent for Claude Code; when it exists, check it has the tools the workflows need". The templates pin no model, like the `opencode.json` template.

Partials in `.factory/partials/`, each one `switch` with one branch per value, every branch reading correctly on its own and containing the marker the proof checks:

| Partial | Switch | Branches | Marker per branch |
| --- | --- | --- | --- |
| `sub-agents.md` | `env.harness` | `opencode`: dispatch with the Task tool, `subagent_type` set to the name in `sub-agent-coding`, `sub-agent-review` or `sub-agent-planning` (defined in `opencode.json`), the bridge note, the fallback rule. `claude`: dispatch with the Agent tool to the sub-agent of that name, defined in `.claude/agents/`. `amp`: one `create_thread` per task, fix or review, `executor: orb`, model from `amp-model-coding` or `amp-model-review`, push before each thread, the brief's closing lines, `send_thread_message`, `read_thread` fallback | `opencode.json`; `.claude/agents/`; `send_thread_message` |
| `workers.md` | `env.workspace` | `orca`: `orca worktree create` and its brief; `orb`: one `create_thread` per plan and its brief; `worktree`: `git worktree add` and the commands to start a session | `orca worktree create`; `parallel-work`; `git worktree add` |
| `worker-setup.md` | `env.workspace` | `orca`: the setup hook (`orca repo list --json`); `orb`: create or switch to the plan branch, `.agents/setup` already ran; `worktree`: run the `setup` setting | `hookSettings`; `already ran`; `the setup setting` |
| `worker-cleanup.md` | `env.workspace` | `orca`: `orca worktree rm`; `orb`: offer to archive the worker thread; `worktree`: `git worktree remove` | `orca worktree rm`; `archive the worker thread`; `git worktree remove` |

No partial names a sub-agent (`agent-coding`, `agent-review`, `agent-planning`) or a model: names and models come from `docs/factory.md`.

Workflows import the partials where 1.024's variants sit: `build-plan` (sub-agents; step 0 worker setup; the TL;DR location line as a `switch env.workspace`), `finish-plan` and `plan-feature` (sub-agents), `start-plan` (workers, cleanup, and the report line as a `switch env.workspace`). Every `description` keeps the operation and drops "Amp thread", "Orca worktree", "OpenCode worker" and sub-agent names. `.factory/AGENTS.md`'s sub-agent rule becomes a three-case `switch env.harness` whose cases import nothing and name the settings keys, so the committed root block shows each harness's rule once, labelled. `.factory/docs/process.md` (not installed, no directives) describes both runtimes for people and how a developer selects an environment.

Release: `metafab check` and `node --test` in fab-basic's CI, run with `@seasb/metafab@2.0.0-next.1`; then the same six previews as Part B's proof, from fab-basic's own checkout; tag `v0.2.0` and push the tag, which is the release. The release notes and README say 0.2.0 is breaking (it removes `agent-harnesses` and needs Metafab 2, `npx @seasb/metafab@next`; Metafab 1 refuses it with exit 4) and how to move from 0.1. Proof for this PR's body: `git ls-remote --tags https://github.com/Traction-Team/fab-basic v0.2.0` shows the tag, `git -C <fab-basic> show v0.2.0:.factory/factory.yaml` shows `format: 2`, and fab-basic's CI run is green on three operating systems.

### Part B: this repository's pull request

1. `npm install --save-dev --save-exact @seasb/metafab@2.0.0-next.1`, so the Git hooks (1.025) run a CLI that reads format 2.
2. `node dist/cli.js update --to ^0.2.0 --setup`: the review summary lists the format change, the partials, the rewritten workflows and the removed `agent-harnesses` skill. As Plan 1.023 specifies, its requirements section lists only the requirements this update adds, the three `.claude/agents/` files, which `--setup` creates. The four that 0.1.x already declared (`docs/factory.md`, `opencode.json`, `orca.yaml`, `docs/roadmap.md`) are not listed and their files are not touched.
3. `.agents/setup`: a new step before the build, `step "Select the Amp environment" select_env`, where `select_env` runs `git config factory.env.harness amp` and `git config factory.env.workspace orb`. Both are repository scope in the orb's own clone, which nobody else shares, and rerunning them is a no-op, so the script stays idempotent. The build, and every later hook-run build and `metafab env` in the orb, read them.
4. `docs/factory.md`: `metafab` stays `node dist/cli.js`; below the table, a short note: "Choose what your agents read: `node dist/cli.js env set harness=opencode` (add `,claude` if you use both; `--global` for every repository) and `node dist/cli.js env set workspace=orca`. Both write `factory.env.*` to Git config, which every worktree of this clone shares. `node dist/cli.js env` shows the selection and where it came from. `.agents/setup` writes `amp` and `orb` into each new Amp orb's Git config. With nothing selected you get every variant, labelled."
5. `node dist/cli.js build`, then the proof.

### Failure paths and edge cases

- **CI** sets no selection, so it builds and checks every variant: `metafab check` validates every branch and import, and the root block is selection-independent, so CI's `git diff --exit-code -- AGENTS.md` stays green.
- **No selection** gives today's behaviour: every variant, labelled.
- **`factory.env.harness codex`** in a developer's global config: one warning per build that `codex` is not declared, and every harness shows.
- **Hooks before step 1** would run the 1.x devDependency and refuse format 2; step 1 comes first, and the PR merges as one commit range, so `main` never has one without the other.
- **A Claude Code user with their own `.claude/agents/agent-coding.md`**: `update` reports it present and never overwrites it.
- **`update` conflicts** in `.factory/` mean a local edit slipped in after 1.024; resolve toward upstream and record the edit in fab-basic.
- **Second run.** The proof script uses new temporary directories each time, so it can be rerun; `build` reports `Up to date.`

## Tests

No new unit tests. The proof, run from the repository root:

```sh
set -eu
fail() { echo "FAIL: $*" >&2; exit 1; }
check() {  # check <dir> <own marker> <other markers...>
  dir=$1; own=$2; shift 2
  grep -rqF --exclude-dir=metafab -- "$own" "$dir/.agents/skills" || fail "$dir lacks $own"
  for other in "$@"; do
    if grep -rqF --exclude-dir=metafab -- "$other" "$dir/.agents/skills"; then fail "$dir contains $other"; fi
  done
  if grep -rqE --exclude-dir=metafab 'factory:(when|endwhen|switch|case|default|endswitch|import)' "$dir/.agents/skills"; then fail "$dir has a directive"; fi
  if grep -rqE --exclude-dir=metafab '^[[:space:]]*\*\*(In|With) .*:\*\*$' "$dir/.agents/skills"; then fail "$dir has a label line"; fi
}
before=$(git hash-object AGENTS.md)
p() { d=$(mktemp -d); node dist/cli.js build --env "$1" --env "$2" --out "$d" >/dev/null || fail "build --out for $1 $2"; echo "$d"; }
check "$(p harness=opencode workspace=worktree)" opencode.json   .claude/agents/ send_thread_message
check "$(p harness=claude   workspace=worktree)" .claude/agents/ opencode.json   send_thread_message
check "$(p harness=amp      workspace=worktree)" send_thread_message opencode.json .claude/agents/
check "$(p workspace=orca     harness=opencode)" "orca worktree create" parallel-work "git worktree add"
check "$(p workspace=orb      harness=opencode)" parallel-work "orca worktree create" "git worktree add"
check "$(p workspace=worktree harness=opencode)" "git worktree add" "orca worktree create" parallel-work
for label in "In OpenCode (OPENCODE=1 is set):" "In Claude Code (CLAUDECODE=1 is set):" "In Amp (AMP_THREAD_ID is set):"; do
  grep -qF "**$label**" AGENTS.md || fail "AGENTS.md lacks $label"
done
test "$before" = "$(git hash-object AGENTS.md)" || fail "a preview changed AGENTS.md"
npm run verify
```

Each preview pins the other variable to one value, so every preview is label-free. Each `mktemp -d` directory is new and empty, which `build --out` requires, so the script can be rerun. The markers come from the partial table above; if A2 words a branch differently, the table and the script change together. Every grep skips the built-in `metafab` skill: it is the CLI's own documentation of directives, so its fenced examples contain a directive line and the words `git worktree add`, which no fab content would.
