# Plan 04: `metafab build`

Compile `.factory/` into the files that agent tools read, and remove obsolete output that Metafab owns.

## Specs

- [Building a factory](../specs/building.md)
- [CLI: Set up a factory](../specs/cli.md#set-up-a-factory)

## Design

Build is split into a pure planner and an applier. [Plan 05](05-check.md) reuses the planner to detect drift without writing.

```ts
planBuild(factory, config, cliVersion): Promise<BuildPlan>
applyBuild(plan): Promise<BuildReport>

interface BuildPlan {
  writes: { path: string; content: Buffer; mode?: number }[];   // desired files
  removals: string[];                                            // owned dirs or blocks to remove
  conflicts: Problem[];                                          // unowned dirs in the way -> exit 5
  warnings: Problem[];                                           // e.g. AGENTS.md block > 300 lines
}

interface BuildReport { changed: { path: string; action: "created" | "updated" | "removed" }[] }
```

`applyBuild` compares each desired file with the disk (text compared with CRLF treated as LF, binary compared byte for byte) and writes only differences. A second run with unchanged inputs reports no changes.

### 1. Compiled skills

For each destination from `destinations(config.agents)` and each factory skill:

1. Copy every file in the skill directory, keeping the executable bit.
2. In `SKILL.md`, keep the frontmatter bytes unchanged and insert this line directly after the closing `---`:

   ```text
   <!-- Generated by metafab build from .factory/<relDir>/. Edit the source, then run metafab build. -->
   ```

3. Write text files with LF line endings. Write binary files unchanged.

The installed directory name is the skill name, so nested groups flatten (`review/security` installs as `security`).

### 2. Ownership

- `isOwned(dir)`: `dir/SKILL.md` exists and contains `<!-- Generated by metafab build`.
- Before any write, check every target directory. If it exists and is not owned, add a conflict. If any conflict exists, `build` writes nothing and exits 5.
- In each managed destination, every owned directory that has no source skill is removed.
- Each destination that is no longer selected has all of its owned directories removed. Unowned directories there are left alone.
- Remove a destination directory (and an empty `.claude/` or `.agents/` parent) only when the removal leaves it empty.

### 3. Built-in `metafab` skill

- Source: `resources/metafab-skill/` in the package. Write its content now, covering every bullet in [Built-in `metafab` skill](../specs/building.md#built-in-metafab-skill), including the design guidance (ask how work moves today, where people decide, what goes wrong; start with four to eight workflows).
- Installed comment: `<!-- Generated by metafab build <version>. Do not edit. Run metafab build to update. -->`. The version lets `check` report an outdated copy.
- Installed when `metafab-skill` is not `false`. Removed by the next build when it is `false`.

### 4. Root `AGENTS.md` block

Render the block exactly as in [Root `AGENTS.md`](../specs/building.md#root-agentsmd):

1. Markers `<!-- factory:start -->` and `<!-- factory:end -->`, then the generated-file comment.
2. The contents of `.factory/AGENTS.md`, trimmed. Omit the section when it is empty.
3. `## Pipeline`, only when the pipeline has entries. A `stop` entry renders as ``N. `name`. Then stop: <stop text>.`` (see open question 1).
4. `## Factory source`, always.

Block placement rules 1 to 4 from the spec: create the file, append the block with one blank line before it, or replace only the text between existing markers. Warn when the block exceeds 300 lines.

When `agents: []`, remove the block and its markers. Remove `AGENTS.md` only when Metafab created it and nothing else remains (the file is then empty).

Malformed markers (a start without an end, or two starts) are an error. `build` stops before writing and asks the user to fix the file.

### 5. Root `CLAUDE.md`

Only when `claude` is selected and `CLAUDE.md` exists:

- If a line matches `^@(\./)?AGENTS\.md\s*$` outside the factory block, leave the file unchanged.
- Otherwise insert at the start of the file:

  ```markdown
  <!-- factory:start -->
  @AGENTS.md
  <!-- factory:end -->
  ```

When `claude` is no longer selected, remove that block.

### 6. `.gitignore` block

Manage the `# metafab:start` / `# metafab:end` block. It lists `.claude/skills/` when `claude` is selected and `.agents/skills/` when another target is selected. Remove the block when no destination is selected. Preserve every other line.

`build` does not edit `.gitattributes`. `init` and `import` add those lines.

### 7. Reporting

Human output lists each changed path with `+`, `~`, or `-`, then a one-line total, or `Up to date.` JSON output is `{ ok, command: "build", changed: [...], problems: [...] }`.

## Tests

- Golden test: the `mark4-like` fixture with `agents: [claude, codex]` produces the expected tree, including the exact `AGENTS.md` block from the spec
- A second build reports no changes
- Changing `agents` from `[claude, codex]` to `[codex]` removes `.claude/skills/` owned output, the `CLAUDE.md` block, and the `.gitignore` line
- `agents: []` removes all owned output and every block, and leaves user text intact
- An unowned `.claude/skills/build-slice/` stops the build with exit 5 and no writes
- A hand-deleted generated comment makes the directory unowned (exit 5)
- Removing a skill from `.factory/` removes its installed directories
- A CRLF source produces LF output; binary supporting files are copied byte for byte; executable bits survive
- `CLAUDE.md` that already contains `@AGENTS.md` is not changed
- `metafab-skill: false` removes the installed built-in skill

## Open questions

1. The spec example renders `stop: The product lead picks the next item` as `Then stop: the product lead picks the next item.`, lowercasing the first letter. Lowercasing breaks names ("Kat approves"). Proposal: render the stop text unchanged, without lowercasing, and update the spec example.
2. Symlinks inside a source skill: the spec says installed output never uses symlinks. Proposal: copy the target's content when the link stays inside `.factory/`; report an error otherwise.
3. Writes are not transactional ([spec open question](../specs/README.md#open-questions)). This plan preflights all conflicts before the first write, which covers the common failure. A crash mid-write is repaired by the next `build`.
