# Plan 2.002: Metastore configuration, document model and a local backend

This plan lays the metastore's foundation, with no command yet. It adds the `metastore` key to `metafab.yaml`; the document model (store paths, formats, properties, titles, hashes, reference mapping, and the writer that turns a stored document back into a file); origin capture from Git and the environment; the backend interface every backend implements; and the **local backend**, a metastore in a directory on this machine that every worktree with the same name shares. It also adds the backend contract test suite that Plan 2.003 runs against the remote backend and that a server such as Metastore Cloud can run against itself. After it merges, nothing a user runs changes except `metafab check`, which now validates the `metastore` key.

## Decisions

Proposed in this plan, for approval:

| Topic | Choice | Reason |
| --- | --- | --- |
| Local backend location | `~/.metafab/metastore/<name>/`, or `$METAFAB_METASTORE_DIR/<name>/` | A committed config cannot hold a per-machine path; one name shares a store across the clone's worktrees; tests point the variable at a temporary directory |
| Local backend storage | Plain files: a catalog, one file per version, content-addressed blobs, a JSON Lines score log, under one directory lock | No native dependency (Node 20 has no stable SQLite); readable for debugging; fast enough for thousands of documents |
| Commit point | Writing `catalog.json` by temporary file and rename | A crash before it leaves orphan version files that the next save overwrites, never a half-saved change |
| Hash | SHA-256 of canonical JSON (keys sorted at every level) of `{ format, properties, body }` for text; of the bytes for `file` | Layout-only frontmatter edits are not changes; key order is ignored, as the protocol compares properties |
| IDs | A ULID helper in `src/util/ulid.ts` | Scores and idempotency keys need sortable unique ids; no dependency needed |
| Locks | One helper, `src/util/lock.ts`, for the local backend (waits up to 10 s) and the mirror (Plan 2.004, never waits) | Same stale-lock rules in both places |

## Design

### Configuration (`src/core/config/types.ts`, `parse.ts`, `validate.ts`)

```ts
export interface SyncWindow {
  where?: Record<string, (string | number | boolean | null)[]>;  // a single value is stored as a one-item list
  recent?: number;
  line: number;
}
export interface MetastoreConfig {
  backend: "remote" | "local";
  url?: string;
  name?: string;
  root: string;              // "docs" when absent; no trailing "/"
  folders?: string[];        // undefined: the default from documents (Plan 2.004 resolves it)
  sync: Record<string, SyncWindow>;
  line: number;              // line of the metastore key
}
```

`Config` gains `metastore?: MetastoreConfig`. `parseConfig` reads it with the existing helpers (`asRecord`, `readString`, `readStringArray`); `validate.ts` reports rules 1 to 6 of the spec and the shape half of rule 7 (window keys end in `/`; unknown window keys; neither `where` nor `recent`; `recent` not a positive integer; `where` values not scalars). Each problem names `.factory/metafab.yaml` and the line of the offending key, with a fix:

- unknown key: `Unknown key "<k>" in metastore`, fix from `didYouMean` over `backend, url, name, root, folders, sync`
- `backend` missing or unknown: `"backend" must be remote or local`
- `url` rules: `"url" must be an https URL, or http for localhost`; `"url" must not contain credentials, a query or a fragment`. The check is the exported `metastoreUrlProblem(url): string | undefined`, which Plan 2.003 also runs on `METAFAB_METASTORE_URL` and `login --url`
- `name` with `remote`: `"name" is only for backend: local`; bad name: the factory name rule's existing message
- `root`: the `folderPathProblem(root)` phrase, or `"root" cannot be .factory or a skill destination`
- folders: `Store folder "<f>" must end with /`, the `folderPathProblem` phrase, `Store folder "<b>" overlaps "<a>"`

Both use `folderPathProblem` from Plan 2.001's `src/util/portable-path.ts`: rules 1, 3 and 4 of [Paths](../specs/metastore.md#paths) and no `!`, `#`, `[` or `]`, as configuration rules 5 and 6 require; not rule 2, since a folder has no extension.
- windows: `Sync window "<k>" needs where or recent`, `"recent" must be a whole number above 0`

### Document model (`src/core/metastore/types.ts`)

Wire-shaped types, matching [Objects](../specs/metastore-protocol.md#objects): `Origin`, `Identity`, `Blob` (`{ sha256, size, contentType }`), `DocumentState` (`"active" | "archived"`), `DocumentVersion`, `DocumentListItem` (without `body`), `VersionSummary`, `ChangeItem` (`save` / `archive` / `restore`), `ChangeRequest` (`{ message, origin, changes }`), `ChangeResult` (`{ path, op, outcome, document: DocumentListItem }`, the document as it is after the change), `ChangeOutcome`:

```ts
export type ChangeOutcome =
  | { kind: "saved"; results: ChangeResult[] }
  | { kind: "conflict"; conflicts: { path: string; baseVersion: number; currentVersion: number; currentState: DocumentState }[] }
  | { kind: "archived"; paths: string[] }
  | { kind: "invalid"; problems: { index: number; path?: string; message: string }[] };
```

`ScoreInput`, `Score`, `ScoreQuery`, `ScoreName`, and `ScoreOutcome` (`saved` with scores, or `invalid` with problems) follow [Scores](../specs/metastore.md#scores).

### Paths (`src/core/metastore/paths.ts`)

```ts
export function storePathProblem(path: string): string | undefined;   // rules 1 to 4: length, extension, no dot segment, portablePathProblem
export function foldPath(path: string): string;                        // lowercase, for rule 5
export function toStorePath(repoPath: string, root: string): string | undefined;   // "docs/plans/x.md" → "plans/x.md"; undefined outside root
export function toRepoPath(storePath: string, root: string): string;
export function inFolders(storePath: string, folders: readonly string[]): string | undefined;  // the longest folder that contains it
```

### Content (`src/core/metastore/content.ts`)

```ts
export interface ReferenceMapping { root: string; storeFolders: readonly string[]; keys: readonly string[] }
export interface DocumentContent { format: DocumentFormat; properties: Record<string, unknown>; body: string; bytes?: Uint8Array }

/** Reads a local file as the CLI will store it: UTF-8 checked, BOM and CRLF removed, frontmatter parsed, references mapped to store paths. */
export function readDocument(storePath: string, bytes: Uint8Array, mapping: ReferenceMapping): { content: DocumentContent; problems: Problem[] };
/** The bytes pull writes for a stored version: references mapped back to repository paths. */
export function writeDocument(content: DocumentContent, mapping: ReferenceMapping): Uint8Array;
export function serializeDocument(format: DocumentFormat, properties: Record<string, unknown>, body: string): string;
export function contentHash(content: DocumentContent): string;          // "sha256:<hex>"
export function contentTypeFor(path: string): string;                   // the spec's extension table, else application/octet-stream
export function propertiesEqual(a: unknown, b: unknown): boolean;        // JSON equality, key order ignored
export function propertyProblems(properties: Record<string, unknown>): string[];  // name rule, 64 KB, finite numbers at any depth
```

- `readDocument` uses `parseDocumentText` (Plan 2.001). A text file that fails `new TextDecoder("utf-8", { fatal: true })` is a problem: `<path> is not UTF-8. Save it as UTF-8, or rename it so it is stored as a file`.
- `propertyProblems` walks every value at every depth: YAML's `.nan` and `.inf` parse to non-finite numbers, so each is a problem, `Property "<top-level name>" holds a number that is not finite at <JSON pointer>`. Top-level names must follow the name rule; keys inside nested mappings are free. The 64 KB limit uses the measurement in [Limits](../specs/metastore.md#limits).
- `serializeDocument` writes markdown as `---\n<yaml>---\n<body>` when properties are non-empty, else the body alone; HTML as `<!--metastore\n<yaml>-->\n<body>`. YAML comes from `stringify(properties, { lineWidth: 0, nullStr: "" })`, keys in stored order; `null` is written as `key:` (a test pins the exact text). Bodies are written with LF.
- Reference mapping applies to the top-level properties named in `mapping.keys` (the `references` of the document's [document folder](../specs/metastore.md#declaring-document-folders)). To store: a string, or string item, that starts with `<root>/` and whose remainder (without `@v<n>`) is in a store folder loses `<root>/`. To write: a value whose path (without `@v<n>`) is in a store folder gains `<root>/`. Every other value is unchanged.
- The hash is computed on the stored form, so `readDocument(writeDocument(x))` hashes equal to `x`: a test round-trips every fixture.

### Title (`src/core/metastore/title.ts`)

`deriveTitle(path, format, properties, body)`: the `title` property when it is a non-empty string after trimming; else the first markdown line matching `/^# \S/`; else the HTML `<title>` text, case-insensitive; else the last path segment.

### Origin (`src/core/metastore/origin.ts`)

```ts
export function normalizeRepoUrl(url: string): string | undefined;
export async function captureOrigin(root: string, env: NodeJS.ProcessEnv, git?: GitRunner): Promise<Origin>;
```

`normalizeRepoUrl` handles `https://[user[:token]@]host[:port]/owner/repo[.git][/]`, `ssh://[user@]host[:port]/owner/repo[.git]` and scp form `user@host:owner/repo[.git]`: host lowercased, credentials and port dropped, `.git` and trailing `/` removed, giving `github.com/owner/repo`. A local path or `file://` URL gives `undefined`. `captureOrigin` runs `git remote get-url origin`, `git symbolic-ref --quiet --short HEAD` (detached → `branch: null`), `git rev-parse HEAD`, and `git status --porcelain` (non-empty → `dirty: true`), each with `runGit` and `execFile`; any failure omits that field. `tool` is `metafab/<cliVersion()>`. `agent` is `METAFAB_AGENT`, else `claude` when `CLAUDECODE` is exactly `1`, else absent. No other variable is read; adding one is a spec change. `session` and `workflow` come from `METAFAB_SESSION` and `METAFAB_WORKFLOW`. Empty variables count as absent.

### Canonical subjects (`src/core/metastore/subjects.ts`)

`parseCanonicalSubject(subject: string): { kind: "doc" | "pr" | "branch" | "commit" | "file" | "url"; repo?: string; name: string } | undefined` accepts only the canonical forms in [Subjects](../specs/metastore.md#subjects): `doc:<store path>`, `pr:<repo>#<digits>`, `branch:<repo>#<name>`, `commit:<repo>#<40 hex>`, `file:<repo>#<repo path>`, `url:https://…`, where `<repo>` is what `normalizeRepoUrl` returns. Backends use it to refuse a non-canonical subject; Plan 2.007 turns input forms into these.

`src/core/metastore/score-rules.ts`: `scoreFieldProblems(score: ScoreInput): string[]` returns one message for each broken rule in the numbered list under [Scores](../specs/metastore.md#scores) (rules 1 to 6, which need no stored data), in that order, such as `criterion "real-names" value 7 is outside the scale 1..5`. The local backend calls it, and Plan 2.007 calls it before sending.

### Backend interface (`src/core/metastore/backend.ts`)

```ts
export interface BackendInfo { protocol: 1; id: string; name: string; identity: Identity; limits: Limits; tokenUrl?: string; capabilities: string[] }
export interface MetastoreBackend {
  /** "local:<name>" or "remote:<url>"; the state file records it (Plan 2.004). */
  readonly id: string;
  info(): Promise<BackendInfo>;
  list(options?: { prefix?: string; archived?: boolean }): Promise<DocumentListItem[]>;   // every page
  get(path: string, version?: number): Promise<DocumentVersion | undefined>;
  versions(path: string): Promise<VersionSummary[] | undefined>;
  readBlob(sha256: string): Promise<Uint8Array | undefined>;
  putBlobs(blobs: { blob: Blob; read: () => Promise<Uint8Array> }[]): Promise<void>;
  apply(request: ChangeRequest, idempotencyKey: string): Promise<ChangeOutcome>;
  recordScores(scores: ScoreInput[]): Promise<ScoreOutcome>;
  listScores(query: ScoreQuery): Promise<Score[]>;
  scoreNames(): Promise<ScoreName[]>;
}
```

`src/core/metastore/limits.ts` holds `DEFAULT_LIMITS` (the spec's table) and `changeLimitProblems(request, limits)`, which both backends and Plan 2.005's push call. It measures sizes exactly as [Limits](../specs/metastore.md#limits) says: UTF-8 lengths of the body, of `JSON.stringify(properties)`, and of `JSON.stringify(request)`, and the item count. `LocalBackend` takes optional `limits` in its constructor (`new LocalBackend({ dir, limits })`), which `info()` reports. The contract suite tests each limit at its boundary (equal passes, one byte over fails) with lowered limits; those tests run only for the built-in backends, because an external server's limits cannot be lowered, and are skipped in the external run.

`src/core/metastore/open.ts`: `openBackend(options: { factory: Factory; config: MetastoreConfig; env: NodeJS.ProcessEnv }): Promise<{ backend: MetastoreBackend; problems: Problem[] }>` (`problems` carries warnings, such as Plan 2.003's damaged credentials file; always empty for `local`). For `local`, the name is `config.name ?? factory.factoryYaml?.name ?? deriveFactoryName(basename(factory.root))` (the existing helper in `src/core/init/name.ts`), and the directory `join(env.METAFAB_METASTORE_DIR ?? join(homedir(), ".metafab", "metastore"), name)`. For `remote`, this plan throws `MetafabError("The remote backend arrives in Plan 2.003")`; Plan 2.003 replaces it.

### Local backend (`src/core/metastore/local/`)

Layout under the store directory, created on first write (with `mkdir -p`); a missing directory reads as an empty metastore:

```text
metastore.json            { "schema": 1, "id": "ms_<ulid>", "createdAt": … }
catalog.json              { "schema": 1,
                            "documents": { "<path>": <DocumentListItem> },          active and archived
                            "idempotency": { "<key>": { "at": …, "outcome": <ChangeOutcome> } } }
versions/<key>/<n>.json   one DocumentVersion with body; <key> = first 32 hex of sha256(foldPath(path))
blobs/<sha256>            bytes
scores.jsonl              one Score per line, in recording order
lock/                     the store lock (src/util/lock.ts)
```

`apply` takes the lock, reads `catalog.json`, and checks every item before writing anything, in this order, returning the first outcome that fails: a repeated idempotency key (returns the stored outcome); a path repeated in the request (`invalid`); `storePathProblem`, `propertyProblems`, body and blob limits, `changeLimitProblems` (`invalid`); a `save` whose folded path equals another document's folded path with different spelling (`invalid`, `differs only in letter case from <path>`); a stale base for any item (`conflict`, listing all); a `save` to an archived path (`archived`); `archive` of an archived or `restore` of an active document, or of a path with no document (`invalid`); an unknown blob (`invalid`). Then it writes the version files and rewrites `catalog.json` with the new documents **and** the idempotency entry for this key in one write (temporary file and `rename`, retried up to 5 times on `EPERM`/`EBUSY` for Windows), dropping idempotency entries older than 24 hours, and releases the lock. Because the key is committed with the change, a crash either loses both or keeps both, and a retry after a saved change always returns the first outcome. Outcomes that save nothing (`conflict`, `archived`, `invalid`) are stored too, in a `catalog.json` write that changes nothing else, as the protocol requires; the CLI uses a new key for every new push, so a push after the person fixes the cause is not affected. A `save` equal to the current version (`propertiesEqual`, body, blob hash) is `unchanged` and writes nothing. `savedBy` is `git config user.name`, else `os.userInfo().username`, with `id: "local:<that name>"`; `savedAt` is one timestamp for the whole change.

`recordScores` refuses a request with more than `limits.scores` scores as one `invalid` problem before reading anything. Then it takes the lock and checks every score: `scoreFieldProblems`, then a `doc` subject's path is in the catalog (`<path> is not in the metastore`) and its version is at most the current version.

`putBlobs` reads each blob's bytes, checks that their length equals `size` and their SHA-256 equals `sha256`, writes them to a temporary file in `blobs/`, and renames it to `blobs/<sha256>`. A mismatch throws `MetafabError` naming the blob and writes nothing for it. A blob already present is skipped. Any problem saves nothing. A score whose `id` is already in `scores.jsonl` returns the stored one. A `doc` subject without `version` gets the current version. Then it appends the new lines with one `appendFile`.

`listScores` reads `scores.jsonl` and filters by `subject`, `prefix` (on `doc:` subjects), `name`, `kind` and `since`, newest first, capped at `limit` (default 100, at most 1,000). `scoreNames` groups by name. Reads take no lock: `catalog.json` is replaced atomically, and a JSON Lines line is complete or absent (a final partial line is ignored).

### Locks (`src/util/lock.ts`)

```ts
export interface LockOwner { pid: number; hostname: string; command: string; startedAt: string }
export async function acquireLock(dir: string, options: { command: string; waitMs: number }): Promise<() => Promise<void>>;
```

`mkdir(dir)` creates the lock; `owner.json` inside names the owner. On `EEXIST`, it reads `owner.json`: an owner on this host whose `pid` no longer exists (`process.kill(pid, 0)` throws `ESRCH`) is stale, and the lock is taken over; an owner with no readable `pid` is held. A held lock is retried every 100 ms until `waitMs`, then `MetafabError` `<dir> is locked by <command> (process <pid>)`, with the fix `Wait for it to finish, or delete <dir> if that process is not running`. Release removes `owner.json` then the directory.

### Contract suite (`test/core/metastore/contract/`)

`describeBackendContract(label: string, make: () => Promise<{ backend: MetastoreBackend; cleanup: () => Promise<void> }>)` registers one `describe` block of backend-agnostic tests. Each test works under its own path prefix, `contract-<ulid>/`, lists and asserts only within it, and uses score names that carry the same ULID, so the whole suite can run in one metastore that already holds data: an external server has no protocol route to create a fresh metastore. `test/core/metastore/contract.test.ts` runs it against the local backend with `METAFAB_METASTORE_DIR` in a temporary directory. Plan 2.003 adds the remote runs to the same file.

## Tests

- Config: a full example parses; every rule gives its message on the right line; `root` defaults to `docs`; `folders: []` is kept as an empty list; a single `where` value becomes a one-item list.
- Paths: one case per rule (no extension, `a/.b/c.md`, 401 characters, a 201-character segment, `a/CON.md`, `a\\b.md`, `a/b .md`); `toStorePath` outside the root; `inFolders` picks the longest folder.
- Content: markdown with and without properties; HTML with and without the comment; CRLF and BOM removed; non-UTF-8 refused; `null` written as `key:`; key order kept; a layout-only change (quotes, indentation, flow list) hashes equal; reference mapping both ways with `@v3`, for a value outside the store folders, and for a key not in `references`; `readDocument(writeDocument(x))` hashes equal for each fixture; a `file` document's hash is its bytes'.
- Title: each source in order.
- `contentTypeFor`: each extension in the spec's table, upper-case extensions, and an unknown one.
- Origin: `normalizeRepoUrl` for https with a token, ssh with a port, scp form, a trailing slash, uppercase host, and a local path; `captureOrigin` in a temporary Git repository (branch, detached, dirty, no remote) and outside Git; `METAFAB_*` variables; empty variables ignored.
- Canonical subjects: each kind accepted; non-canonical forms refused (`#42`, `pr:42`, `doc:docs/plans/x.md` with a leading root is accepted as a path but `doc:../x.md` refused).
- Locks: a second acquirer waits and then gets the lock; `waitMs: 0` fails at once with the owner's command; a stale owner (a pid that is not running) is taken over; an `owner.json` without a pid is held.
- Contract suite (local): the cases in the proves line, plus list ordering and `prefix` and `archived`, `get` of a version and of a missing path, `versions` newest first, title and origin stored, one `savedAt` per change, `restore` with the archived version as base, case-variant refused, limits refused before writing, score field rules (no `value` and no `label`; `pr` without `revision`; `doc` version past the newest; non-canonical subject), `listScores` filters and `scoreNames` counts.
- Local backend only: two child processes (`execFile` of a small script) each apply 20 changes to different paths at once and every change is saved with no lost catalog entry; a crash simulated by writing version files without the catalog leaves the catalog unchanged and the next save succeeds; a change applied by one `LocalBackend` instance and retried with the same key by a new instance (a new process) returns the first `saved` outcome, not a conflict; a `conflict` outcome is stored, so the same key returns the same conflict after the cause is fixed, and a new key succeeds; `recordScores` with 101 scores is refused with nothing appended; a blob whose bytes do not match its hash or size is refused and leaves no file; `.nan` in a nested list is a property problem; `root: docs/.mirror` and a 201-character folder segment are configuration errors; a partial last line in `scores.jsonl` is ignored.
- Score rules: one case per numbered rule in the spec, including a criterion value outside `scale` and a `url` subject with a `revision`.

## Open questions

1. Which other agent tools set a documented environment variable that `origin.agent` should read? Proposal: none in this plan (decided: `METAFAB_AGENT` and `CLAUDECODE` only); file an intake note per tool when its variable is confirmed, as a spec change.
2. Should the local backend keep score files per month to keep reads fast? Proposal: no until a local store holds more than 10,000 scores; the file layout belongs to the CLI and can change.
