# Plan 2.005: Metastore push saves the mirror in one atomic change, with diff, mv, archive and restore

This plan makes the metastore writable from a working tree. `metafab metastore push -m <message>` reads every modified and new file in the store folders, checks them against the path rules, the backend's limits and the factory's document rules, and saves them in one atomic change with the repository's origin. A stale base saves nothing and leaves a conflict copy to merge; `push --resolved` saves the merge. `diff` shows what a push would change, `mv` moves a document or folder atomically, and `archive` and `restore` retire and bring back documents. After it merges, an agent can edit a plan in `docs/plans/` and save it for every developer without a branch, a commit or a pull request.

## Decisions

Proposed in this plan, for approval:

| Topic | Choice | Reason |
| --- | --- | --- |
| Deleted local files | Reported by push, never archived | A wiped folder must never archive the team's documents; archiving is explicit |
| Conflict copy without `--resolved` | The push stops for that document, before anything is sent | Its base is known to be stale; resending would only write another copy |
| Rules on documents push does not save | Do not stop the push, except a shared `unique` value | An old, invalid document must not block every save, but a new duplicate must |
| A rerun after a lost response | A stale base with identical content counts as saved; the rest is sent once more with a new key | Recovers a push whose process died, without asking the person |
| Folders in `archive` | Refused | A mistyped folder must not archive dozens of documents |
| `mv` content | The local file when it exists, modified or not; else the current version | An agent often moves and edits a plan together |

## Design

### Collecting a change (`push.ts`)

```ts
export interface PushOptions { paths?: string[]; message: string; resolved?: boolean }
export interface PushResult {
  saved: { path: string; version: number; outcome: "saved" | "unchanged" }[];
  recorded: { path: string; version: number }[];   // already saved by an earlier run
  conflicts: string[];                               // repository paths of conflict copies written
  deleted: string[];                                 // reported, not archived
  problems: Problem[];
}
export async function push(ctx: MirrorContext, options: PushOptions): Promise<PushResult>;
```

1. `assertNotTracked`; take the lock; `readState`; `readIndex`; `scanMirror` under the given paths, or all store folders.
2. Candidates: local files whose hash differs from their entry, and files with no entry. Deleted files (entry, no file) go to `deleted`. A link is a problem: `<path> is a symbolic link; the metastore stores files only`.
3. A candidate whose entry has `remote` stops unless `resolved`: problem `<path> has a conflict copy at <copy>`, fix `Merge it into <path>, then run metafab metastore push <path> -m <message> --resolved`.
4. For each candidate: `readDocument` problems, `storePathProblem`, `propertyProblems`, and the backend's limits from `info()` (body or blob size). Then the document rules: for each document folder with a candidate, `documentProblemsFor(factory, folder, documents, { indexed, focus })`, where `documents` holds every local file under that folder (so `documentProblemsFor` applies the folder's `match`, and a candidate that does not match gets no schema check), `indexed` maps the repository path of each active index entry under the folder that has no local file to its stored properties, so `unique` values of documents outside the sync windows still count, and `focus` is the set of candidate paths. `changeLimitProblems` checks the count and size of the whole change.
5. Any error stops the push: every problem is printed, nothing is sent, exit 1. Warnings (missing references) are printed and do not stop it.
6. Build the `ChangeRequest`: `message`, `origin = captureOrigin(...)`, and one `save` per candidate with `baseVersion = resolved && entry.remote ? entry.remote : entry?.version ?? 0`, the stored-form `properties` and `body`, or the `blob`. `putBlobs` for `file` documents first.
7. `backend.apply(request, ulid())`, and handle the outcome:
   - `saved`: for each result, set the entry `{ version: result.document.version, hash }` and clear `remote`; replace the index entry with `result.document`, the list item the backend returned; `removeConflictCopy`.
   - `conflict`: for each conflict, `backend.get(path)`. When its content hash equals the candidate's, record the entry at that version and drop the candidate. When every conflict was like that, send the remaining candidates once more with a new key and handle that outcome without this retry. Otherwise write a conflict copy for each conflict whose content differs, set `remote`, and exit 1 with `<n> documents changed in the metastore since you pulled them`, listing each copy and the fix from [Conflicts](../specs/metastore.md#conflicts). Nothing is saved.
   - `archived`: exit 1, `<path> is archived`, fix `Run metafab metastore restore <path>, or save it at another path`.
   - `invalid`: exit 1, each problem printed beside its path from `index`.
8. Write the state and the index; release the lock.

The summary lists the saved documents with their versions, the unchanged ones, the recorded ones, and the deleted files with the fix `Run metafab metastore archive <path> -m <message> to archive it, or metafab metastore pull <path> to restore it`. With nothing to push: `Nothing to push`, exit 0. `--json` returns `PushResult`.

### Focus for document checks (`src/core/documents/check.ts`)

`DocumentSet` gains `focus?: ReadonlySet<string>`. With a focus, `documentProblemsFor` keeps only problems on focused paths, and reports a duplicate `unique` value on the focused document when either side of the pair is focused, naming the other path. `metafab check` passes no focus and is unchanged.

### Diff (`diff.ts`)

`diff(ctx, { paths, remote }): Promise<{ path: string; base?: number; patch: string }[]>`. For each modified or new file (or each named one), the base is `backend.get(path, entry.version)`, or the current version with `remote`, or nothing for a new file. Both sides are rendered with `writeDocument`, so references and frontmatter are compared as pull would write them, and diffed with `createTwoFilesPatch` from the `diff` package, labelled `<repo path>@v<n>` and `<repo path>`. A `file` document prints `Binary file <path> differs (<base size> → <local size> bytes)`. With `remote`, the current version is always fetched, even when a conflict copy exists, because the copy may be stale.

### Move (`move.ts`)

`move(ctx, { from, to, message })`:

1. Resolve `from` with `resolvePathArgs`. A folder moves every active document under it in the index; `to` must then be a folder, and each path keeps its remainder.
2. For each pair: the target must have no active or archived document in the index (`<to> already exists in the metastore`) and no local file (`<to> already exists locally`), and must pass `storePathProblem`. The content is the local file, else `backend.get(from)`. The archive base is the entry's version, else the index's version. Targets are checked against the document rules, as push does.
3. One request: an `archive` of each source and a `save` of each target with base 0, message `<message> (moved from <from argument>)`.
4. On `saved`: write each target file, remove each source file, move state entries (target `{ version: 1, hash }`), update the index. On `conflict`: nothing changes locally; exit 1 with `Pull, then move again`.
5. Warn about each index document whose `references` properties name a source path: `<doc> still refers to <old path>`, fix `Update it to <new path>`.

### Archive and restore (`archive.ts`)

- `archive(ctx, { paths, message, force, base })`: folders are refused (`archive takes documents, not folders`). For each document: a local file with changes is refused unless `force` (`<path> has changes you have not pushed`, fix `Push them, or pass --force to discard them`); the base is the entry's version, else `base` (allowed only with one path), else exit 1 `<path> has no recorded version`, fix `Pass --base <n>; metafab metastore log <path> lists its versions`. One request with every `archive`. On `saved`: remove each local file, conflict copy and state entry; mark the index entries archived. A `conflict` changes nothing: exit 1 with `Pull, then archive again`.
- `restore(ctx, { paths, message })`: for each path, `backend.versions(path)`; the newest must be archived (`<path> is not archived`); its version is the base. One request with every `restore`; then `pull` of those paths.

### Commands

`push [<path>…] -m <message> [--resolved]`, `diff [<path>…] [--remote]`, `mv <from> <to> -m <message>`, `archive <path>… -m <message> [--force] [--base <n>]`, `restore <path>… -m <message>`. A missing `-m` is exit 1, `<command> needs a message: -m "<what changed>"`. Each replaces its stub from Plan 2.003.

### Edge cases

- **Two pushes in one working tree.** The second stops on the lock.
- **Two developers saving the same plan.** The second gets a conflict copy; neither loses work.
- **A file edited while push runs.** Push hashes the bytes it read and sends those; the state records that hash, so the newer edit shows as modified afterwards.
- **A push over the limits.** Refused before sending, naming the limit; the person pushes folders separately.
- **Interrupted after `apply` but before the state is written.** The next push finds identical content behind each stale base and records it.
- **No network.** Exit 6 with nothing changed locally.

## Tests

All run against the local backend and the test server through Plan 2.004's helper.

- Push: modified and new files saved in one request (the test server's `requests` shows one `POST /v1/changes`) with the origin's branch and commit; the state and index updated; an unchanged file not sent; `Nothing to push`; a deleted file reported and not archived; a schema error in a pushed plan stops everything with the problem on the property's line and no request sent; a schema error in an unpushed plan does not stop the push; a `unique` duplicate between a pushed and an unpushed plan stops it, reported on the pushed one; a missing `needs` target warns; a body over the limit is refused before sending; a link is refused.
- Conflicts: another writer saves first → conflict copy at `docs/.metastore/remote/plans/x.md`, exit 1, nothing saved for the other documents in the push; push without `--resolved` refused; after merging, `--resolved` saves at the next version and removes the copy; the backend moving on again writes a new copy.
- Recovery: the test server's "apply then drop" fault with retries exhausted, then a second push: the identical documents are recorded, a document changed since is sent once more, and the server holds exactly one new version of each.
- Archived: a save to an archived path is exit 1 with the restore fix.
- `diff`: a modified file against its base; `--remote` against the current version, also when a conflict copy exists and the metastore has moved past it; a new file against empty; a binary file line.
- Rule set: a pushed `notes.txt` in a `match: "*.md"` folder gets no schema check; a pushed plan whose `code` equals an index-only plan's (outside the window, no local file) stops the push, reported on the pushed plan.
- Index: after a push, the index entry equals the backend's returned list item, `savedBy` included.
- `mv`: a document (local file moved, state and index moved, old path archived, message suffix); a folder of three documents in one request; a target that exists is refused; a reference warning; a conflict changes nothing locally.
- `archive`: refuses a folder; refuses a modified file, and `--force` archives it; `--base` for a deleted local file; local file, copy and entry removed. `restore`: an archived plan comes back as a new version and is pulled; an active one is refused.
- `documentProblemsFor` with a focus, in `test/core/documents/`.
