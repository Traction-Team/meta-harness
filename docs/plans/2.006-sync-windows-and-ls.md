# Plan 2.006: Pull follows sync windows, pins what it is asked for, and `store ls` lists the whole store

Log folders grow without end: every pull request adds a changelog entry, and finished plans, reviews and research pile up. Dragonfly's mirror reached 1,100 files and 20 MB, and most of it buried the documents that mattered in every `grep`. This plan adds sync windows: a folder in `metafab.yaml` can keep only documents whose properties match (`where`) or the most recent units (`recent`). A pull copies what is in the window and removes clean copies that left it, never local work. `pull <path>` fetches anything and pins it; `unpin` releases it. `metafab store ls` lists every document from the local index, with or without a local file, and `metafab check` treats a document in the index as present. After it merges, a mirror holds the open plans and recent logs, and agents reach the rest with `ls` then `pull <path>`.

## Decisions

Proposed in this plan, for approval:

| Topic | Choice | Reason |
| --- | --- | --- |
| Ranking for `recent` | The `YYYY-MM-DD` at the start of the unit's name, then the newest `savedAt` of its documents; undated units after every dated one | A bulk import gives every document the same `savedAt`; the name states the unit's date |
| Units | First segment below the window's folder, extension removed | A note with its sightings, or a research page with its files, is useful only whole |
| `--where` on a list property | Matches when the list contains the value | `--where needs=docs/plans/x.md` finds the plans that need `x` |
| Value comparison | As text: `String(value) === given` | Command-line values are text; `--where pr=12` matches the number 12 |

## Design

### Windows (`windows.ts`)

```ts
export interface Unit { folder: string; key: string; paths: string[]; date?: string; savedAt: string }
export function windowFor(storePath: string, windows: Record<string, SyncWindow>): { folder: string; window: SyncWindow } | undefined;  // longest folder wins
export function unitsOf(folder: string, entries: Map<string, IndexEntry>): Unit[];
export function inWindow(index: MirrorIndex, windows: Record<string, SyncWindow>): Set<string>;   // store paths whose unit is in its window
```

- `unitsOf` groups active entries under `folder` by `key` = the first segment below the folder with everything from its last `.` removed when that segment is the last one (a file), else the segment itself (a folder). So `intake/x.md` and `intake/x/s1.md` share `x`; `research/y.md`, `research/y.html` and `research/y/data.csv` share `y`.
- A unit matches `where` when any of its documents has, for every named property, a value equal (`propertiesEqual` for scalars) to one of the listed values, or a list value that contains one.
- `recent`: sort units by `date` descending (units with no date last), then `savedAt` descending, then `key`; take the first `recent`.
- A unit is in when it matches `where` or is among the `recent`. Paths in folders with no window are always in.

### Pull (`pull.ts`)

The wanted set becomes `inWindow(index, mirror.windows)` ∪ pinned entries ∪ local files that are modified, new or have a conflict copy, unless `options.all`, which wants every active document. Clean local files of active documents outside the wanted set are removed with their state entries, as archived ones already are. `pull <path>` covers its documents whatever the window, and sets `pinned: true` on each document it names directly or below a named folder; `--all` pins nothing.

### Status (`status.ts`)

`outside` counts the active documents that `inWindow` does not select, whether or not they have a local file (a pinned or modified one is still outside its window); the summary line is `<n> documents are outside the sync windows (metafab store ls)`. Pins and local changes stay in their own status lines. For a document outside its window, status reports by what the next pull will do:

| Local file | Status line |
| --- | --- |
| None | Counted in `outside` only |
| Clean, pinned | `B` when behind, else nothing |
| Clean, not pinned | `O <path>  outside its window; the next pull removes it`, which takes precedence over `B` as the spec orders them |
| Modified, or with a conflict copy | `M` or `C` as usual |

### State (`state.ts`)

`unpin(mirror, storePaths | folders)`: clears `pinned` under the lock. Nothing else changes; `pinned` was already in the entry type.

### `ls` (`ls.ts`)

```ts
export interface LsOptions { prefixes: string[]; where: [string, string][]; sort: "path" | "saved"; limit?: number; archived?: boolean; remote?: boolean }
export interface LsLine { mark: " " | "M" | "↓" | "P" | "A"; path: string; version: number; savedAt: string; title: string; entry: IndexEntry }
export async function ls(ctx: MirrorContext, options: LsOptions): Promise<LsLine[]>;
```

- Without `remote`, it reads the index; no index is exit 1, `No index yet`, fix `Run metafab store pull`. With `remote`, it lists the backend with `archived: true`, whatever `--archived` says, then calls Plan 2.004's `ensureMirrorDirs` and takes the mirror lock, so it works in a fresh clone with no `docs/` yet, rewrites the whole index from that list, and only then filters the lines it prints, so the index always holds archived documents too.
- Prefixes accept repository paths, store paths and partial names (`docs/plans/2.0`); with none, every document.
- `--where key=value` may repeat; all must match. A malformed one is exit 1, `--where needs key=value`.
- The mark: `A` for archived (only listed with `archived`), `↓` when there is no local file, `M` when the local file is modified, `P` when pinned and clean, blank otherwise.
- Output: one line per document, `<mark> <YYYY-MM-DD> v<version>  <repo path>  <title>`, sorted by path or by `savedAt` newest first, cut to `limit`. `--json` prints `{ documents: LsLine[] }` with the full entries.

### `unpin`

`unpin <path>…`: `resolvePathArgs`, then `unpin`. Prints how many pins it cleared and `The next pull removes the ones that are clean and outside their window`.

### Check (`src/core/check/index.ts`)

Plan 2.003's `backendIdFor`, awaited, gives the id `openBackend` would give, without opening anything. When `config.store` is set, `runCheck` reads the index for that id and passes, as `indexed` to `documentProblems`, each active entry that has no local file, by repository path, with its stored properties after `writeDocument`'s reference mapping (so references compare in repository form). A reference to a document that is only in the index is then not reported, and a `unique` value it holds still collides. A missing or damaged index, or another store's, means no `indexed` set; a damaged one adds its warning. `check` makes no network request.

### Edge cases

- **A window that keeps nothing** (`recent: 0` is invalid by configuration rule 8, but a `where` that matches nothing): the folder holds only local work and pins.
- **An undated folder of research.** Ranked by `savedAt` alone.
- **Changing a window.** The next pull applies it: units that left are removed when clean, units that entered are written.
- **Removing the `sync` key.** The next pull copies the folder in full.
- **A pinned document archived.** Removed when clean, like any archived document; the pin goes with its entry.

## Tests

Against the local backend and the test server through Plan 2.004's helper, with a store of plans in every status, ten dated reviews, two undated research pages, and intake notes with sightings folders.

- Windows: `where` only, `recent` only, both; longest folder wins (`plans/` and `plans/archive/`); units from a note and its sightings folder and from a research `.md`/`.html` pair with a folder; undated units ranked after dated ones; ties broken by `savedAt`; a bulk-imported set with one `savedAt` ranked by the names.
- Pull: only units in the window written; a clean file that left the window removed with its empty folder; modified, new, pinned and conflicted files kept; `pull <old review>` pins it and a second pull keeps it; `unpin` then pull removes it; `pull docs/reviews/` pins every review under it; `--all` writes everything and pins nothing, and the next plain pull removes the extras.
- Status: the outside count includes a pinned document and a modified one outside their windows; a clean, unpinned local file outside its window is reported as removed by the next pull; a pinned, clean one that is behind is listed as behind.
- Check: an index-only plan's `code` collides with a local plan's, reported on the local file.
- `ls`: every document with marks, including `↓` and `P`; `--where status=ready`; `--where needs=<path>` on a list; two `--where`; `--sort saved`; `--limit`; `--archived` adds `A` lines; `--remote` without `--archived` rewrites the index with the archived documents still in it; `--remote` in a fresh clone with no `docs/` creates the folders and the index; JSON shape; no index is exit 1.
- Check: a plan whose `needs` names a plan only in the index gives no warning; with the index of another store it warns; `check` sends no request (the test server's `requests` is empty).
