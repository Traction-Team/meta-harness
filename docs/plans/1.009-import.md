# Plan 1.009: `metafab import` and the review summary

Copy a fab into `.factory/`, record its upstream, build it, and print a risk-ordered review summary. The review summary module is shared with `update` ([Plan 1.010](1.010-update-diff-detach.md)).

## Specs

- [Sharing: Importing a fab](../specs/sharing.md#importing-a-fab)
- [Sharing: Review summary](../specs/sharing.md#review-summary)
- [Sharing: Safety model](../specs/sharing.md#safety-model)
- [CLI: Share a factory](../specs/cli.md#share-a-factory)

## Design

### `import <source> [--agents <list>] [--force] [--adopt]`

Preflight (no writes; any failure leaves the repository unchanged):

1. Resolve the root with `resolveNewFactoryRoot`. If `metafab.yaml` already has `upstream`, stop with exit 5 and one problem on `.factory/metafab.yaml`: `This factory already has an upstream`, fix `Use metafab update or metafab detach`.
2. Resolve and fetch the source ([Plan 1.008](1.008-sources.md)). Exit 3 or 4 on failure.
3. Select targets as `init` does.
4. Plan adoption against the selected destinations, passing the incoming fab so overlapping names follow the conflict rule.
5. Compute file conflicts: every incoming path whose local file exists (in `.factory/` or as an adopted skill) with different content (EOL-insensitive). Without `--force`, list all of them and stop with exit 5 (decided 2026-10-29).
6. Collect adoption consent: `--adopt`, else the terminal, else exit 2 naming `--adopt`.

Apply:

7. If the repository has no factory: create `.factory/metafab.yaml` with `agents` and add `.gitattributes` lines. Do not create `factory.yaml` or `AGENTS.md`.
8. Apply adoption.
9. Copy the fab's `.factory/` into the local `.factory/`, keeping modes.
10. `setUpstream`.
11. Run `build`.
12. Print the review summary, comparing the factory before step 8 with after step 10.

### Fetch hygiene

`import` is the first command that fetches, so it fixes two gaps [Plan 1.008](1.008-sources.md) left (intake `2026-10-26-sources-hardening`, items 1 and 2):

- HTTPS and local-path fetches leave their `mkdtemp` directory behind. Add an optional `cleanup?: () => Promise<void>` to `FetchedFab`, set by the HTTPS and path fetchers only (Git and npm return cache paths, which stay). `import` opens a `try` straight after the fetch in step 2 and calls `cleanup` in its `finally`, so every later stop (file conflicts, exit 2 for consent, a failed build) removes the directory too. Every later caller of `fetchFab` does the same. `cleanup` is best effort: it never throws, so it cannot hide the command's own error.
- A link whose target does not exist is reported twice, in both `extract.ts` and `path.ts`: once by `createLinks` and once by the realpath check in `verifyLinks`. Keep the creation-time message, and have `verifyLinks` skip links whose creation already failed. (Dropping the creation message instead would turn a Windows EPERM on symlink creation into a false "target does not exist".)

Git resolution and fetches (`resolve` and `fetchFab`, which both reach the network) pass `interactive: true` when standard input is a terminal and `--json` is absent, so an SSH key with a passphrase can prompt. Otherwise Git runs with `GIT_TERMINAL_PROMPT=0`. This answers the Git prompt question that Plan 1.008 left for this plan (decided 2026-10-29).

### Review summary (`core/summary.ts`)

```ts
summarise(before: FileTree, after: FileTree, ctx: { title: string; preserved?: string[]; conflicts?: string[]; notes?: string[] }): Summary
renderSummary(summary): string        // human text
```

Classification, in the spec's order:

1. **Runs code on your machines**: anything under `scripts/`, any file with an executable bit, and any non-Markdown file in a skill directory
2. **Changes every agent session**: `AGENTS.md`, `factory.yaml`
3. **Workflows**: grouped per workflow directory; a new workflow shows its title
4. **Skills**: other skill directories
5. **Local edits preserved** (update only)
6. **Conflicts** (update only)

Other files (templates) go in a final **Other** group. See open question 1.

Per entry: status (`A`, `M`, `D`, `C`), path, `+n -m` line counts for text, `new, executable` for new executables. Annotations:

- `factory.yaml`: describe pipeline changes in words (`pipeline: finish-slice added after review-slice`, `removed`, `moved`, `stop changed`)
- `SKILL.md`: `allowed-tools changed` when that frontmatter field differs

Footer: `Nothing was committed. Review the changes with git diff.` JSON returns the same groups as structured data.

## Tests

- Import into an empty repository creates `metafab.yaml`, `.gitattributes`, the copied factory, the upstream entry, and installed skills, and creates no `factory.yaml` placeholder when the fab has none
- Import never copies a source `metafab.yaml` or `.factory/README.md`
- A differing local file stops import and lists it; `--force` replaces it
- An existing upstream stops import
- A failing fetch or invalid fab leaves `git status` clean
- No temporary fetch directory remains after an import from HTTPS or a local path: on success, on a file conflict without `--force`, and on exit 2 for consent. Point `TMPDIR` and `TEMP` at a fresh scratch directory for the call and assert it is empty afterwards
- A tarball with a hard link whose target is missing gives exactly one problem; a local path with a dangling symbolic link gives one; a stubbed link-creation failure gives only the creation message
- Adopted skills that overlap the fab follow the conflict rule
- Summary snapshot matches the spec example
