# Plan 2.007: `metastore score` records a pinned score and `metastore scores` lists them

A judge, a script or a person can now record what they decided about a plan, a pull request, a branch, a commit, a repository file or any URL, and list those scores later. `metafab metastore score <subject>` turns any input form (`docs/plans/x.md`, `#42`, `branch:feat/x`, a GitHub URL) into the canonical subject, resolves the commit or document version that was read, adds the origin, and records the score. Because a backend never calls Git or GitHub, the CLI resolves every revision itself. `metafab metastore scores` lists scores by subject, by folder or by name. Scores work with `folders: []`, so a repository can keep its plans in Git and still record scores. Plan 2.008's scorers build on it.

## Design

### Input subjects (`src/core/metastore/scores/subject.ts`)

```ts
export type InputSubject =
  | { kind: "doc"; storePath: string; version?: number }
  | { kind: "pr"; repo: string; number: number; revision?: string }
  | { kind: "branch"; repo: string; name: string; revision?: string }
  | { kind: "commit"; repo: string; sha: string }
  | { kind: "file"; repo: string; path: string; revision?: string }
  | { kind: "url"; url: string };
export function parseSubject(input: string, ctx: { repo?: string; mirror?: Mirror; root: string; cwd: string }): InputSubject;
export function canonicalSubject(subject: InputSubject): string;
```

Forms, in the order they are tried:

1. `https://github.com/<owner>/<repo>/pull/<n>` with anything after the number (`/files`, `#…`) → `pr`. `…/tree/<branch…>` → `branch` (the rest of the path is the branch name). `…/commit/<sha>` → `commit`. The repository is `github.com/<owner>/<repo>`, lowercase host only.
2. Any other `https://` URL → `url`, without its fragment or trailing `/`. `http://` is refused: `Use an https URL`.
3. `#<n>`, `pr:<n>`, `pr:<n>@<sha>` → `pr` in `ctx.repo`.
4. `branch:<name>`, `branch:<name>@<sha>` → `branch` in `ctx.repo`. The name follows `git check-ref-format --branch` rules, checked without Git (no `..`, no space, no `~^:?*[\\`, no leading `-`, no trailing `/` or `.lock`).
5. `commit:<sha>` (4 to 40 hex) → `commit` in `ctx.repo`.
6. Anything else is a path: a repository path relative to `cwd`, a repository path from the root, or a store path, with an optional suffix: `@v<n>` (a document version) or `@<4 to 40 hex>` (a file's commit). Inside a store folder → `doc`. Otherwise, a path that exists in the working tree or at `HEAD`, or at the given commit → `file`. Otherwise exit 1, `<input> is not a document, a repository file or a subject`, fix listing the forms. The suffix is split at the last `@` only when what follows matches one of the two forms, so a path containing `@` elsewhere still works.

A short form with no `ctx.repo` (no `origin` remote) is exit 1, `This repository has no origin remote`, fix `Give a full URL, such as https://github.com/<owner>/<repo>/pull/42`. `@v<n>` on a `file` is exit 1, `@v<n> pins documents; pin a file to a commit with @<sha>`, and `@<sha>` on a document is exit 1, `@<sha> pins files; pin a document to a version with @v<n>`.

### Resolving revisions (`resolve.ts`)

`resolveSubject(subject, ctx: { root, git: GitRunner, gh: CommandRunner, mirror?, state? }): Promise<{ subject: string; version?: number; revision?: string; run?: Record<string, unknown> }>`:

- `doc`: `version` as given. Without one, when the local file is modified (its hash differs from its state entry), new (no entry), or deleted (an entry and no file), exit 1 with the spec's fix; otherwise no version, so the backend pins the current one. A document with no local file and no state entry (outside the sync windows) has nothing unsaved and is pinned by the backend.
- `pr`: a given `@<sha>` is expanded as for a commit when the repository is this one, else must be 40 hex. Without one: the host must be `github.com` (else exit 1, `Give the head commit: pr:<n>@<sha>`); run `gh pr view <n> --repo <owner>/<repo> --json headRefOid --jq .headRefOid` with `execFile`. `ENOENT` → exit 1, `gh is not installed`, same fix; a non-zero exit → exit 1 with the first line of `gh`'s standard error.
- `branch`: given `@<sha>` as above. In this repository: `git rev-parse --verify --quiet refs/heads/<name>`, else `refs/remotes/origin/<name>`. Another repository: `git ls-remote https://<repo>.git refs/heads/<name>`. Not found → exit 1, `Branch <name> not found`, fix `Give its commit: branch:<name>@<sha>`.
- `commit`: in this repository `git rev-parse --verify <sha>^{commit}`; another repository needs 40 hex.
- `file`: with `@<sha>`, `git rev-parse --verify <sha>^{commit}` expands it, and `git cat-file -e <commit>:<path>` must succeed (else exit 1, `<path> is not in commit <sha>`); no `run.modified`. Without it, `git rev-parse HEAD`, and `git status --porcelain -- <path>` non-empty → `run: { modified: true }`. Outside Git: exit 1, `A repository file needs a Git repository`.
- `url`: nothing to resolve.

`CommandRunner` is a small `execFile` wrapper, injected in tests so no test calls `gh` or the network.

### Building and recording (`record.ts`)

`buildScore(input: { subject; resolved; fields; origin }): ScoreInput` assigns `id = ulid()`, merges `--file` fields with flag overrides (`name`, `value`, `label`, `scale`, `rationale`, `model`), merges `run` from the file with the resolver's `run`, and refuses `id`, `subject` and `origin` in the file (`<field> is set by metafab`). `--scale 1..5` parses two finite numbers. `scoreFieldProblems` (Plan 2.002) runs before sending; problems are exit 1 with each listed. `recordScore(backend, score)` calls `recordScores([score])`; `invalid` is exit 1 with the backend's problem.

### Listing (`list.ts`)

`listScores(backend, { target?: string; name?; since?; limit? })`: a target that names a folder (ends in `/`, or is a store folder) becomes `prefix` with the root removed; any other target goes through `parseSubject` and `canonicalSubject`, and becomes `subject`. No revision is resolved for `pr`, `branch` and `file`, whose canonical form has none. A `commit` target is part of its canonical form, so a short commit of this repository is expanded with `git rev-parse --verify <sha>^{commit}` first, and a commit of another repository must be 40 hex (exit 1 otherwise, `Give the full commit for another repository`). `--since` accepts `YYYY-MM-DD` or an ISO time. `limit` defaults to 50.

Each line: `<recordedAt as YYYY-MM-DD HH:MM>  <name>  <value>[/<scale.max>] or <label>  <subject>@v<version> | @<first 7 of revision>  <scorer or ->`. `--json` prints the backend's scores.

### Commands

`score` and `scores` replace their stubs. `score` always takes the subject as its one positional argument, because a `--file` cannot hold one; a missing subject is exit 1, `score needs a subject`. Its summary: `Recorded <name> <value or label> on <canonical subject>@<pin>`.

### Edge cases

- **Retry.** The score's `id` is created once per command, so a retried request records it once.
- **`folders: []`.** Every path is a `file` subject; scores still record.
- **A branch name with slashes** in a `tree` URL: the whole remainder is the name.
- **A document pinned to a version it never had**, or a path not in the metastore: the backend's `invalid` problem is printed.
- **Windows.** Paths given with `\` are converted to `/` before parsing.

In `test/core/metastore/scores/`, against the local backend and the test server.

- `parseSubject`: every input form in the spec's table, including a pull request URL with `/files`, a tree URL with `feat/x/y`, an uppercase host, a URL with a fragment; `http://` refused; a path inside and outside the store folders; a missing path; `@v3` on a file and `@abc123` on a document refused; `docs/specs/cli.md@<sha>` pinned to that commit, and refused when the commit lacks the path; a path containing `@` with no pin suffix; a short form without an origin.
- `resolveSubject`: `gh` stub returns a head; `gh` missing; `gh` failing; a non-GitHub host without `@sha`; a local branch ahead of origin resolves to the local commit; only a remote branch; neither; a short commit expanded; a file with and without changes; a document with unsaved changes refused and with `@v2` accepted.
- Recording: the backend pins the current version; `@v7` kept; flags over `--file`; `id` in the file refused; missing `value` and `label` refused with no request sent; a retried request (test server "apply then drop" fault on `/v1/scores`) records once.
- Listing: by document, by folder `docs/plans/`, by `#42`, by `commit:<7-char sha>` (expanded, matching a score recorded with the full commit), by `--name`, with `--since` and `--limit`; line format; JSON.
- A locally deleted plan without `@v<n>` is refused; a plan outside the window with no local file is pinned by the backend.
