# Plan 1.017: Dogfood Metafab in this repository

This repository installs its own factory with `.factory/scripts/link.mjs`. The script commits symlinks in `.claude/skills/` and `.agents/skills/` and writes the `AGENTS.md` block. As a result, `metafab check` reports about 20 errors here, and `metafab build` refuses to run (exit 5). This plan switches the repository to `metafab build`: the symlinks and `link.mjs` go, the installed skills become ignored generated copies, Git hooks and the Orca setup step rebuild them, and CI runs the spec's build-and-check recipe. After it merges, we use Metafab every day before v1, and any gap we hit is ours to find, not a user's.

## Decisions

| Topic | Choice | Reason |
| --- | --- | --- |
| Targets | `agents: [claude, codex, opencode]` | The same two destinations as today; the people here use Claude Code, Codex and opencode |
| Hooks | `git-hooks: true` only if `file:.` gives every checkout a working `node_modules/.bin/metafab` after `npm install`. Otherwise commit `git-hooks: false`, and Plan 1.012 turns it on once `@seasb/metafab` is on npm | We test the hooks by using them, but a hook that prints `metafab: build failed` on every checkout for every teammate is worse than none |
| Duplicate skills in opencode | Nothing to do: keep both destinations | opencode reads both `.claude/skills/` and `.agents/skills/` in this repository today and lists each skill once (observed 2026-11-02). Plan 1.012 verifies this for Cursor and Copilot |
| Which CLI builds this repository | `node dist/cli.js` from this checkout. `@seasb/metafab` is not on npm until Plan 1.012 | The repository is the CLI |
| `.factory/scripts/check.mjs` | Keep it for plans, roadmap, intake and changelog. Remove its skill, pipeline, link and `AGENTS.md` block checks, which `metafab check` now covers | One validator per concern |
| `npm run verify` | `typecheck`, `test`, then `npm run factory`, where `factory` is `npm run build && node dist/cli.js build && git diff --exit-code -- AGENTS.md CLAUDE.md .gitignore .gitattributes && node dist/cli.js check && node .factory/scripts/check.mjs` | AGENTS.md already says to run verify before every push. A stale committed block fails it through `git diff`, as in CI, and installed copies are simply refreshed. `factory` builds the CLI first, so it never installs skills with a stale `dist/`. `CLAUDE.md` does not exist here; `git diff` on a missing path is fine |

## Design

### Switch-over, in this order, in one commit

0. Write `orca.yaml` (below) first. The `init` in step 3 will show the Orca suggestion, because the file runs `node dist/cli.js build` and not `metafab build`. That is expected here. Record the suggestion text in the TL;DR as evidence that it works.
1. `git rm` every symlink in `.claude/skills/` and `.agents/skills/`. They are unowned output, so adoption would otherwise try to move them into `.factory/skills/`.
2. Delete `.factory/scripts/link.mjs`. In `lib.mjs`, remove `TARGET_DIRS`, `renderBlock`, `applyBlock`, `BLOCK_START`, `BLOCK_END`, `desiredLinks` and `linkState`, and `listSkills` and `readPipeline` if nothing else uses them. `check.mjs` and `next.mjs` must still run.
3. `npm run build`, then `node dist/cli.js init --agents claude,codex,opencode --git-hooks` (or `--no-git-hooks`, per the Hooks decision). Expected writes: `.factory/metafab.yaml`, `.gitattributes`, the `.gitignore` block, the `AGENTS.md` block replaced in place (the markers are already `<!-- factory:start -->` / `<!-- factory:end -->`), the installed skills including `metafab`, and the three hooks in `.git/hooks/`.
4. Read the new `AGENTS.md` block diff carefully. Its text changes from the link.mjs wording to Metafab's. Fix any regression in `.factory/AGENTS.md`, never in the generated block.

### `.factory/AGENTS.md`

- Commands: replace `node .factory/scripts/check.mjs` as the factory check with `npm run factory`, and keep `check.mjs` for docs. Add one line: "In this repository `metafab` is `node dist/cli.js`: run `npm run build` first."
- "Publishing docs changes": docs-only commits still run `node .factory/scripts/check.mjs`. A change to `.factory/` must also run `npm run factory`, because the `AGENTS.md` block is committed. Say this in the list.
- Remove the "Do not edit the skill links" sentence if it lives here. The generated "Factory source" section already says not to edit installed copies.

### `.factory/README.md`

Rewrite "Installing it": run `npm install && npm run build && node dist/cli.js build`. Hooks rebuild after checkout, merge and rebase. New worktrees build through `orca.yaml`. Update the folder table and the scripts table (no `link.mjs`).

### `orca.yaml`

```yaml
scripts:
  setup: |
    npm install
    npm run build
    node dist/cli.js build
```

Orca's per-repository setup setting (today `npm install`) may override the committed file. List "clear the Orca repository setup command" as a manual step in the TL;DR, and confirm with `orca worktree create ... --setup run` that the new worktree has `.claude/skills/metafab/`.

### Hooks in this repository

The hooks look for `node_modules/.bin/metafab`, then `metafab` on `PATH`, then `npx @seasb/metafab@<version>`. None of these finds this checkout's CLI until 1.0 is on npm, so a hook in a new worktree prints `metafab: build failed` unless the developer ran `npm link` once. The `orca.yaml` step covers Orca worktrees anyway. Try `"@seasb/metafab": "file:."` as a devDependency so that `node_modules/.bin/metafab` exists. Keep it only if `npm ci` works with it on all three CI operating systems; otherwise document `npm link` in the README. Record which one in the pull request.

### CI (`.github/workflows/ci.yml`)

The `factory` job becomes the spec recipe with this checkout's CLI:

```yaml
- run: npm ci
- run: npm run build
- run: node dist/cli.js build
- run: git diff --exit-code -- AGENTS.md CLAUDE.md .gitignore .gitattributes
- run: node dist/cli.js check
- run: node .factory/scripts/check.mjs
```
