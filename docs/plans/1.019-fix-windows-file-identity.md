# The containment test fails on Windows CI now and then

## What happens

On `windows-latest`, `test/core/sources/containment.test.ts > roots a link at the destination when no ancestor is .factory` sometimes gets `<destination>\.factory` instead of `<destination>`. A link stored under `assets/` is then checked as if it were inside `.factory/`, so the containment boundary is wrong. Seen on PR #18 (12 Nov) and main run 42458407210 (8 Nov). It passes on a re-run of the same commit.

## Why

`src/core/sources/containment.ts:25` matches directories by `stat().dev` and `stat().ino`, read as JavaScript numbers. NTFS file IDs are 64 bits, and a double keeps only 53, so different directories created close together can get the same `ino`. `src/core/build/plan.ts:439` (is `CLAUDE.md` the same file as `AGENTS.md`) uses the same comparison and can give a false match in the same way.

## The fix

Call `stat(path, { bigint: true })` at both places and compare the `bigint` `dev` and `ino`. Keep one small helper (`sameFile(a, b)`) if both callers can share it without a new module outside `owns`. Do not change the realpath fallbacks or what each function returns. Add a unit test that the comparison uses the exact values. Leave the existing containment tests as they are: they are the regression test.
